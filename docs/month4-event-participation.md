# M4-13 — регистрация и участие

Миграция `031_event_participation.sql` расширяет события M4-12. В карточке доступны выбор ученика, подача заявки, управление участием, история и приватные документы. Онлайн-оплата и отметка «оплачено» отсутствуют.

## Доступ и возраст

Родитель записывает только активного ребёнка с действующей подтверждённой семейной связью. При каждом запросе сервер заново проверяет аккаунт, роли и связь. Ученик записывает только себя, при известной дате рождения и достижении `EVENT_SELF_REGISTRATION_MIN_AGE` полных лет на дату запроса в часовом поясе события. Значение `0` (по умолчанию) закрывает самостоятельную запись до согласования порога; настройка принимает целое число 0–100. Это продуктовое правило, не утверждение о законодательном возрасте. Переменная передаётся через оба compose-файла; после изменения нужен перезапуск backend.

Участием управляют администратор и назначенные в карточке действующие ответственные сотрудники. Остальные сотрудники, включая руководителя, не получают список участников и документы только по праву чтения карточки. Семья видит только заявки доступных ей детей. Ответственный может записать активного ученика; родитель и ученик не могут самостоятельно подтвердить участие.

## Статусы и места

| Действие | Результат |
|---|---|
| Заявка в открытый период при свободном месте | `requested`, место резервируется |
| Заявка при заполненной вместимости | `waitlisted`, место не резервируется |
| Ответственный подтверждает заявку | `requested` → `confirmed` |
| Ответственный переводит из ожидания | `waitlisted` → `confirmed`, только при свободном месте |
| Семья или ответственный отменяет до начала события | `requested` / `confirmed` / `waitlisted` → `cancelled` |
| Ответственный отмечает результат после начала | `confirmed` → `attended` / `no_show` |
| Администратор отменяет событие | Активные заявки → `cancelled`; история и документы сохраняются |

Период подачи — `[registration_starts_at, registration_ends_at)` и статус события `published`. Подтверждение уже поданных заявок возможно после закрытия регистрации, но до начала события. Автоматического продвижения очереди нет. После отмены можно подать новую заявку, если регистрация ещё открыта; прежняя запись остаётся в истории.

Статусы `requested`, `confirmed`, `attended`, `no_show` учитываются в вместимости. Запись, переходы, отмена события и изменение вместимости блокируют строку события `FOR UPDATE` до конца транзакции. Проверка количества выполняется после получения блокировки; два запроса не могут занять последнее место одновременно. Уменьшение вместимости ниже занятых мест запрещено. Частичный уникальный индекс запрещает повторную неотменённую заявку одного ученика. Редакция заявки защищает от устаревших изменений. История добавляется триггером и защищена от UPDATE/DELETE; DELETE заявки также запрещён.

## Уведомления и документы

Подтверждение/отмена участия создают уведомление в кабинете и email outbox в той же транзакции. Изменение начала, окончания, места или часового пояса опубликованного события уведомляет семьи всех заявок `requested`, `confirmed`, `waitlisted`. Отмена события делает это перед отменой заявок. При ошибке откатываются данные, история, аудит и уведомления. Повторная проверка семейного доступа при чтении уведомления и отправке email сохраняется.

Документы до 10 МиБ загружаются в конкретную заявку, проверяются существующим валидатором типов файлов и хранятся приватно в БД. Просмотр метаданных, загрузка и скачивание доступны администратору, действующим ответственным и семье с текущим доступом к ребёнку. Старый загрузивший пользователь не сохраняет доступ после отзыва семейной связи/назначения. URL не является разрешением: каждый запрос авторизуется заново, ответ `private, no-store`, скачивание как attachment с sandbox/nosniff. Отмена участия не удаляет документы.

## API

Все пути начинаются с `/api/v1`; изменения требуют CSRF. Основные контракты: [OpenAPI событий](openapi-events.yaml), [OpenAPI участия](openapi-event-participation.yaml).

- `GET /events/{id}/candidates?search=&page=1` — доступные ученики; `active` означает возможность регистрации с текущим возрастным правилом.
- `GET /events/{id}/registrations?page=1` — только доступные заявки, `occupied`, `can_manage`, `self_registration_min_age`.
- `POST /events/{id}/registrations` — `{student_id}`.
- `POST /events/{id}/registrations/{registration_id}/actions` — `{action,revision}`, действие равно целевому статусу.
- `GET /events/{id}/registrations/{registration_id}/history` — неизменяемая история.
- `GET/POST /events/{id}/registrations/{registration_id}/documents` — список с пагинацией / загрузка `{name,data}` (base64).
- `GET /events/{id}/registrations/{registration_id}/documents/{document_id}` — защищённое скачивание.
- `POST /events/{id}/actions` с `{action:"cancel",revision}` — отмена события.

Проверки: интеграционные тесты PostgreSQL в `event_participation_integration_test.go`, браузерный сценарий `event-participation.spec.ts` для desktop и 360 px. Проверяются конкуренция, дубликаты, период, возраст, права, отзыв доступа, документы, история и атомарность уведомлений.
