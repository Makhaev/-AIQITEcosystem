# Программы и модули

Модуль `backend/internal/modules/programs` реализует HTTP → service → repository. Миграция `004_programs.sql` применяется при запуске. Контракт — [OpenAPI](openapi.yaml), интерфейс — `frontend/src/screens/Programs.tsx`.

## Программы

Поля: ID, название, описание, `draft`/`active`/`archived`, даты создания и изменения. Название обязательно, от 1 до 200 символов; описание необязательно, до 5000 символов. Пробелы по краям удаляются. При создании статус по умолчанию `draft`. Одинаковые названия разрешены и не объединяют записи.

GET `/programs`: поиск по буквальной подстроке названия без учёта регистра, включая кириллицу; фильтр статуса; страницы по 20 записей, максимум 100. `%` и `_` не становятся wildcard. Порядок стабилен по нормализованному названию и ID. GET `/programs/{id}` возвращает карточку и массив `modules`, упорядоченный по номеру.

POST `/programs` и PATCH `/programs/{id}` доступны администратору. Непереданные поля PATCH сохраняются, `description=null` очищает описание; название и статус не могут быть null. Архивирование — `status=archived`, восстановление — `draft` или `active`. Карточка, модули и существующие связи групп остаются в БД; физического удаления через API нет. Изменения текста, статуса и архива записываются в audit в той же транзакции.

## Модули

Поля: ID, `program_id`, название, описание, `position`, даты создания и изменения. Номер — положительное целое, до 2147483647. Пара `(program_id, position)` уникальна в PostgreSQL. Одинаковый номер в разных программах разрешён; пробелы в нумерации допустимы.

POST `/programs/{id}/modules` создаёт модуль; GET/PATCH `/programs/{id}/modules/{module_id}` читает/редактирует его. Проверяются как программа, так и принадлежность модуля указанному ID. Перенос между программами через тело PATCH запрещён строгой схемой JSON. Конфликт номера возвращает 409 `module_position_exists`; весь запрос откатывается. В архивной программе создание и изменение модулей возвращают 409 `program_archived`; сначала восстановите программу.

Модули можно добавлять и редактировать в черновике или активной программе. При изменении модуля обновляется также дата изменения программы. Audit содержит событие модуля и ID, без текста описания.

## Программа группы и модуль занятия

Для серверных ограничений добавлены таблицы `groups`, `group_enrollments` и `lessons`. Управление группами, зачислениями, вместимостью и переводами реализовано в [модуле групп](groups-and-enrollments.md). Занятия, проверка пересечений и сохранённый состав реализованы в [расписании и журнале](lessons-and-journals.md).

Триггер `groups_active_program` проверяет статус программы при создании группы и изменении её `program_id`; черновик/архив отклоняются. Строка программы блокируется `FOR SHARE`, поэтому проверка сериализуется с архивированием. Существующая связь при архивировании сохраняется; изменения прочих полей группы не требуют повторного назначения программы. Go-guard `programs.RequireActive(ctx, tx, id)` позволяет будущему API вернуть понятный конфликт до SQL-записи; триггер защищает всех писателей БД.

Программа занятия выводится сервером БД из группы. Триггер не принимает несовпадающий явный `program_id`. Составной внешний ключ `(group_id, program_id)` ссылается на группу, `(module_id, program_id)` — на модуль. Ссылка на чужую программу отклоняется при INSERT и UPDATE. `module_id` необязателен. Изменить программу группы при наличии ссылающихся занятий также нельзя: история не становится несогласованной.

Go-guard `programs.RequireGroupModule(ctx, tx, groupID, moduleID)` загружает программу группы из БД, проверяет принадлежность модуля и не доверяет ID программы из тела клиента. Составные FK дополнительно защищают результат при конкурентных изменениях.

## Права

Admin управляет всеми программами и модулями. Leader читает все. Teacher читает программы групп, где он основной педагог, или программ собственных занятий. Curator читает программы групп закреплённых за ним учеников, включая историю зачислений. Несколько ролей суммируются; без подтверждённых связей ограниченные роли видят пустой список. Чужой ID возвращает 404, включая вложенные запросы модулей. Параметры фильтра не меняют область доступа; `total` также отфильтрован.

Middleware проверяет каждую операцию. Репозиторий повторно проверяет текущую сессию, блокировку и роли внутри транзакции. GET использует единый снимок для карточки/модулей и списка/количества. Мутации сериализуются общей административной блокировкой с изменением пользователей; данные и audit сохраняются атомарно.

## Проверки

Интеграционные тесты с PostgreSQL проверяют CRUD, нормализацию, статусы и архив, nullable PATCH, поиск на кириллице, буквальные wildcard, пагинацию, порядок и уникальность модулей, конфликты при редактировании и параллельном создании, роли и вложенные чужие ID, отзыв сессии и CSRF. Отдельные SQL-проверки подтверждают активную программу группы, модуль своей программы, необязательный модуль и сохранение истории. Конкурентный тест подтверждает ожидание архивирования до фиксации назначения группы.

Playwright проверяет создание/изменение программы и модуля, поиск, порядок, конфликт номера, архив и восстановление, чтение для трёх ограниченных ролей и ошибки ID. Проверены клавиатура, WCAG A/AA через axe, основной текст от 16 px и отсутствие горизонтального переполнения на 1440 и 360 px. Браузерные ответы API вымышленные; реальные права и БД отдельно проверяются Go-тестами.
