# R11: отчёт о Docker и HTTPS

Дата проверки: 16 октября 2026 года. **R11 выполнено частично; приёмка не закрыта.** Рабочая копия подготовлена для Docker/HTTPS, а фактический HTTPS-прогон выполнен нативными Windows-процессами. Docker Engine в этом окружении отсутствует. Публичный сервер, домен и доступ к ним не предоставлены; опубликованного адреса пилота нет.

## Подготовленные изменения

- `compose.pilot.yaml` — самостоятельный HTTPS-стенд с отдельным томом PostgreSQL. Наружу публикуются только HTTP/HTTPS nginx; у БД и backend нет host ports. Сеть БД внутренняя.
- `deploy/pilot.env.example` — шаблон окружения без настоящих секретов. `APP_ORIGIN` обязан быть HTTPS-origin того же `PILOT_HOST`. Сертификат и ключ подключаются из внешнего каталога только для чтения; в образы они не попадают.
- Общие `frontend/nginx-http.conf` и `nginx-server.conf` используются HTTP- и HTTPS-конфигурациями. Включены HTTP → HTTPS, TLS 1.2/1.3, HSTS, лимит тела 1 МиБ, единые JSON-ошибки прокси и request ID. Нативный error log nginx отключён; структурированный access log не содержит URL, заголовков, cookies или контактов.
- `scripts/verify-r11.mjs` создаёт уникальный Compose-проект и пустую БД, собирает образы, повторяет миграции, создаёт первого администратора, проверяет HTTPS/вход/CSRF/cookies, реально останавливает БД и backend, проверяет логи, сохраняет отчёт и удаляет только собственный тестовый проект с его томом. Случайные пароли остаются в памяти/окружении и не выводятся в отчёт. Локальный сертификат создаётся на 24 часа и доверяется только проверяющим клиентом.
- В CI добавлена задача `docker-https` с сохранением отчёта без секретов. Удалённый запуск этой задачи пока не подтверждён.

## Что действительно запущено

Изолированный локальный стенд: собранные Go-бинарники, новая PostgreSQL на `127.0.0.1:55433`, nginx на HTTP `127.0.0.1:18080` и HTTPS `localhost:18443`, production-сборка frontend. Сертификат самоподписанный, с SAN `localhost` / `127.0.0.1`; клиент проверял подпись и имя, используя этот сертификат как явно заданное доверие. Проверка TLS не отключалась.

## Что осталось для приёмки

1. В Docker-окружении выполнить `node scripts/verify-r11.mjs` и получить `status: passed`, сохранив отчёт с версиями и ID образов. Документированная последовательность: config → build → up db → migrate дважды → admin → up backend/frontend → nginx/HTTP-проверки → остановки/восстановление → проверка логов → удаление тестового проекта.
2. На согласованном сервере настроить DNS и действительный публичный сертификат, выполнить [инструкцию пилота](operations.md#https-пилот-r11), проверить HTTPS из внешней сети и отсутствие доступных извне портов БД/backend.
3. На этом же опубликованном пилоте подтвердить вход владельца, cookies/CSRF, health, nginx, лимиты и ошибки. Остановки БД/backend проводить до загрузки рабочих данных, в согласованное окно проверки.
4. Передать владельцу фактический HTTPS-адрес и административный доступ: учётную запись создать с временным паролем, переданным отдельно безопасным способом; потребовать смену при первом входе. Пароли, cookies и полные контакты не включать в отчёт. Bootstrap первого администратора создаёт постоянный пароль — он вводится самим владельцем через скрытый ввод, как описано в README.

Без этих результатов локальный нативный HTTPS-прогон и подготовленная конфигурация не закрывают R11.
