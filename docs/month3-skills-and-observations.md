## Цель месяца и границы M3 01

Результат месяца: в системе доступны подтверждённые наблюдения и учебные работы
ученика, а Student 360 отражает его образовательный контекст с проверяемыми
источниками. Основания, указанные заказчиком: SKL01–SKL03, HW01, PRJ01,
STU01–STU04. Полные тексты этих требований нужно связать с приёмочными
сценариями до приёмки; одни идентификаторы не доказывают их покрытие.

M3 01 включает версионную модель навыков, наблюдения, проверку, исправления,
управляемую видимость и блок наблюдений в Student 360. Учебные задания,
сдача и проверка работ, проекты и их критерии относятся к отдельным задачам
месяца 3. Успешная приёмка M3 01 не означает выполнения всего месяца,
HW01, PRJ01 или всех STU01–STU04.

Цели ученика, рабочее место куратора, задачи внимания и передача доступа
описаны в [M3 02 — Цели и работа куратора](month3-goals-and-curator.md).
Достижение цели опирается на проверенные источники и не заменяет определение
текущего уровня навыка по утверждённой методике.

Задания всех форматов, попытки сдачи, проекты, достижения и портфолио
описаны в [M3 03 — Задания и проекты](month3-assignments-and-projects.md).
Реальная отправка из кабинета ученика принимается отдельно в месяце 4.

Наблюдение описывает конкретное поведение в контексте. Оно не является
диагнозом, характеристикой личности или публичной оценкой ребёнка.
Рейтинги учеников, лидерборды, общий «балл личности» и сравнение детей
между собой не создаются.

## 2. Модель навыков

Модель содержит идентификатор, номер версии, название, область применения,
навыки и историю согласования. У навыка есть устойчивый ключ, название,
описание и упорядоченный набор уровней. Каждый уровень имеет ключ, понятное
название, описание наблюдаемого поведения и признаки, по которым его можно
обосновать. Порядок уровней не означает разрешение складывать или усреднять их.

Методист редактирует черновик модели. Жизненный цикл модели:
`draft → review → published → archived`; возврат из проверки в черновик
требует комментария. Руководитель образования утверждает публикацию;
автор не утверждает собственную редакцию даже при совмещении ролей.
Новая версия создаётся копированием с явным указанием источника.

В опубликованной и архивной версии содержание неизменно. Новые наблюдения
используют опубликованную версию, применимую к выбранному образовательному
контексту. Версия модели назначается контексту явно и сохраняется в наблюдении;
сервер проверяет соответствие. Наличие только совпадающего названия навыка
недостаточно. Порядок назначения модели контекстам входит в утверждение
области применения до запуска.

Архивирование запрещает новые наблюдения по модели, но не скрывает прежние
и не мешает их проверке или исправлению в исходной версии. Смена модели
не переписывает прошлое. Сопоставление навыков между версиями можно хранить
как справочную связь; перенос уровней и объединение источников допускаются
только по отдельно утверждённым правилам совместимости. По умолчанию версии
рассматриваются раздельно.

## 3. Состав наблюдения

Одно наблюдение относится к одному ученику и одному навыку одной версии модели.

| Поле | Правило |
| --- | --- |
| Ученик | Обязательная ссылка на доступного ученика; имя не заменяет ID |
| Автор | Текущий пользователь при создании; сервер не принимает подмену автора |
| Дата наблюдения | Дата/время факта, не позднее текущего времени; ввод и отображение в Europe/Moscow. Время создания хранится отдельно |
| Контекст | Занятие либо разрешённое событие; ссылка, дата и сохранённое краткое описание контекста |
| Навык и версия | Ссылка на навык конкретной версии, действовавшей для выбранного контекста |
| Факт поведения | Наблюдаемое действие или высказывание, 1–4000 символов при отправке; отдельно от оценки |
| Трактовка | Объяснение связи факта с признаками навыка, 1–4000 символов при отправке |
| Признаки и предполагаемый уровень | Выбранные признаки исходной версии; уровень может быть гипотезой автора, но не становится текущим уровнем ученика автоматически |
| Источники | Контекст и, при наличии, ссылки на разрешённые приватные файлы или существующие учебные работы; вложение не обязательно |
| Проверка | Решение, проверяющий, время, комментарий и проверенная редакция |
| Видимость | По умолчанию `internal`; отдельные автор и время изменения видимости |
| История | Корневой ID наблюдения, номер редакции, предшествующая редакция, причина исправления и журнал действий |

Черновик может быть неполным по содержанию, но ученик и разрешённый контекст
обязательны уже при создании. При отправке обязательны дата, навык/версия,
факт и трактовка. Нельзя отправить будущий факт, чужой навык, уровень другой
версии или недоступный источник. Наблюдение не создаётся автоматически
из отсутствия на занятии, оценки активности группы или открытия файла.

Педагог выбирает участника своего занятия из разрешённого состава. Если
снимок журнала сформирован, использовать включённых участников снимка;
иначе — зачисления на дату занятия. Текущее зачисление не даёт права писать
о чужом историческом занятии. Состав и права проверяются сервером при создании,
сохранении и отправке, включая конкурирующее изменение состава или педагога.

Для события требуется действующая сущность с датой, участниками и назначенными
сотрудниками. Свободный текст «событие» не даёт права выбрать произвольного
ученика. Если такого источника прав в проекте ещё нет, создание по событиям
остаётся недоступным с явным объяснением; новый модуль событий сюда не входит.

## 4. Проверка и исправления

| Переход/действие | Кто и при каких условиях |
| --- | --- |
| Создание и изменение `draft` | Автор при действующем доступе к ученику и контексту |
| `draft → submitted` | Автор; полная серверная проверка полей, ссылок, версии и полномочий |
| `submitted → draft` | Проверяющий возвращает с обязательным комментарием либо автор явно отзывает подачу; решение фиксируется в истории |
| `submitted → reviewed` | Уполномоченный проверяющий, отличный от автора; проверяет факт, трактовку, контекст и ссылки |
| Исправление `reviewed` | Создание новой черновой редакции с обязательной причиной; прежняя остаётся неизменной |

`reviewed` означает, что конкретная редакция прошла установленную проверку.
Это не самостоятельное подтверждение текущего уровня ученика и не разрешение
на публикацию. В `submitted` содержание заморожено до возврата или отзыва.
Проверяющий не переписывает текст автора незаметно: замечания возвращаются
автору, все действия подписываются фактическим исполнителем.

Новая редакция проходит `draft → submitted → reviewed` заново. Для одного
наблюдения допустим один открытый черновик исправления; параллельное создание
второго отклоняется с предложением открыть существующий. Пока исправление
не проверено, прежняя проверенная редакция остаётся действующей, если её
не отозвали. После проверки новая становится действующей атомарно;
предыдущая сохраняется как заменённая, без двойного учёта в уровне.

При обнаружении ошибочного наблюдения проверяющий может немедленно отозвать
его действительность с причиной. Отзыв не удаляет запись: она исключается
из оснований уровня и обычной опубликованной хронологии, а уполномоченным
сотрудникам доступна в истории. Восстановление требует новой проверки.
Это отдельный признак действительности, а не изменение содержания `reviewed`.

Ученик, автор исходного факта и идентичность навыка/версии не подменяются
исправлением. При ошибочном ученике или навыке прежнее наблюдение отзывается,
создаётся новое с верными ссылками; доступ к обеим записям проверяется отдельно.
Автор исправления и первоначальный автор сохраняются раздельно.

Повтор запроса не создаёт дубликат редакции или решения. Сохранение проверяет
ревизию; при конфликте не теряет введённый текст. Решение, новая редакция,
состояние публикации и история фиксируются согласованно в одной транзакции.

## 5. Видимость и публикация

В M3 01 предлагаются два режима:

- `internal`: запись доступна автору и уполномоченным проверяющим в пределах
  их области; черновик доступен автору, передача на проверку открывает
  проверяющему соответствующую редакцию.
- `student360`: конкретная проверенная редакция опубликована в образовательном
  блоке Student 360 для сотрудников, которым разрешены ученик и эти сведения.

Второй режим не означает открытый интернет, доступ всем сотрудникам или семье.
В существующем Core карточки родителей не являются аккаунтами; создание
кабинетов, отправка семье, публичные ссылки и публикация во внешние сервисы
не входят в M3 01. Если заказчик подразумевает семейную публикацию, до запуска
нужен отдельный согласованный канал и проверяемые права получателя.

Публикация — отдельное действие уполномоченного сотрудника после `reviewed`
с предварительным просмотром точной редакции и аудитории. Автор не публикует
собственную запись даже при совмещении ролей. Непроверенные и отозванные
редакции публиковать нельзя. Повтор действия не создаёт новую публикацию.

Исправленная редакция получает `internal` и требует отдельной публикации.
При её утверждении прежняя редакция помечается заменённой и снимается
с текущей публикации: нельзя продолжать показывать устаревший вывод как
действующий. История прежних публикаций сохраняется для уполномоченных лиц.
Отзыв публикации немедленно закрывает её обычное чтение и доступные через неё
вложения; повторная публикация требует нового явного действия.

## 6. Предлагаемое распределение полномочий

| Роль | Полномочия в M3 01 |
| --- | --- |
| Педагог | Наблюдения только о разрешённых участниках своего контекста; работа со своими черновиками, отправка и инициирование исправления |
| Методист | Подготовка модели; проверка наблюдений только в явно назначенной области, без самоутверждения |
| Руководитель образования | Утверждение модели; публикация и отзыв публикации наблюдений в назначенной области, без самопубликации |
| Куратор | Чтение опубликованного образовательного блока закреплённых учеников; роль сама по себе не открывает чужие черновики и не даёт права проверки |
| Руководитель (`leader`) | Чтение опубликованных наблюдений доступных учеников; без автоматического права менять текст или решение |
| Администратор | Управление пользователями и назначением согласованных полномочий; техническая роль сама по себе не делает его автором, проверяющим или публикатором |

Для методиста и руководителя образования требуется явное назначение области
проверки/публикации, например конкретных групп; роль не открывает все
наблюдения автоматически. Ширина области фиксируется до запуска в матрице
доступа. Права на модель и права на персональные наблюдения независимы.

Действующее право проверять или публиковать включает чтение соответствующих
редакций и истории в этой области. Прежнее авторство не сохраняет доступ
после его отзыва. Смена педагога, куратора, области проверки или блокировка
сотрудника учитываются при следующем запросе, включая прямые URL и файлы.
Архивирование ученика сохраняет историю; создание новых наблюдений запрещено,
проверка уже поданных и исправление истории доступны по действующим правам.

## 7. Определение текущего уровня

До утверждения методики интерфейс показывает хронологию и текст
«Методика определения уровня не утверждена». Числового балла, автоматически
выбранного уровня и графика роста нет. Отсутствие наблюдения означает
«Нет наблюдений», а не уровень 0 или минимальный уровень модели.

После утверждения методика получает собственные ID, версию и дату принятия,
ссылку на совместимую версию модели и контрольные примеры. Она должна явно
определять период, минимальную достаточность источников, требуемые признаки,
повторные наблюдения, противоречия, давность, пропуски и правила пересмотра.
Реализация формулы или процедуры начинается только по этому утверждённому
контракту; универсальный конструктор методик в M3 01 не требуется.

Основания — действующие `reviewed`-редакции подходящей версии модели;
черновики, поданные, отозванные и заменённые редакции не учитываются.
Недостаточность данных даёт отдельное состояние «Недостаточно данных».
Конфликтующие источники разрешаются методикой; нельзя молча выбирать
последний или самый высокий уровень. «Последнее наблюдение» показывается
как факт хронологии, не как синоним текущего уровня.

У каждого вывода сохраняются навык, версия модели и методики, период,
использованные ID редакций наблюдений, объяснение, время формирования
и автор решения, если методика предусматривает ручное утверждение.
Результат должен воспроизводиться по этим источникам. Исправление или отзыв
основания требует пересчёта либо повторного ручного решения по методике;
до его завершения прежний уровень помечается неактуальным.

В Student 360 публикуется только вывод с доступными данной аудитории
источниками. Внутренние наблюдения не должны скрыто влиять на видимый семье
или другой ограниченной аудитории результат. В пределах M3 01 для обычного
образовательного блока используются опубликованные основания; внутренний
разбор доступен только проверяющим и не выдаётся за общий опубликованный
результат. При недостаточных правах на источники показывать доступную
хронологию без раскрытия скрытого вывода и количества закрытых записей.

Версии моделей показываются раздельно с явными подписями. Новый выпуск
модели или методики не переписывает старые выводы; новые результаты сохраняют
свою версию и историю пересмотра. В одной шкале не соединять уровни разных
моделей без утверждённой совместимости.

## 8. Student 360, файлы и интерфейс

В Student 360 добавить образовательный блок: хронологию опубликованных
подтверждённых наблюдений, фильтры периода, навыка и версии, контекст занятия
и переход к разрешённым источникам. Черновики и очередь проверки находятся
в отдельных рабочих представлениях и не выглядят подтверждёнными фактами.
Хронология сортируется по дате наблюдения и ID, имеет пагинацию; дата проверки
показывается отдельно. Применение фильтра не меняет сохранённый текущий уровень.

В форме факт и трактовка — отдельные поля с пояснениями. Показаны версия
модели, состояние, видимость, автор, решение проверки и история исправлений.
Для проверки доступны текст, признаки и источники, команды подтверждения
и возврата. Публикация явно указывает, какая редакция и кому станет доступна.

Приватный файл привязывается только при наличии разрешения на его использование
для этого ученика и контекста; знание ID не даёт доступа. При открытии
проверяются права на файл и редакцию наблюдения. Публикация наблюдения не
делает файл публичным и не расширяет его аудиторию автоматически. Если файл
не доступен предполагаемой аудитории, публикация отклоняется с объяснением
до исправления состава источников или их разрешений через файловый модуль.

Отзыв прав, публикации или удаление файла по правилам файлового модуля
не оставляют действующую обходную ссылку. Недоступный источник обозначается
уполномоченному проверяющему; его потеря учитывается методикой достаточности,
а не считается автоматически низким уровнем навыка. Защищённые тексты
и ссылки не включать в общие технические логи и общедоступные списки.

Существующие блоки Student 360, контакты семьи и ограничения педагога
сохраняются. Наличие наблюдения не открывает полную карточку ученика.
Использовать общую тему и компоненты; поддержать desktop и 360 px,
клавиатуру, ошибки у полей, сохранение ввода при сбое и явные состояния
загрузки, пустого результата, недостаточных прав и ошибки сервера.
Ошибка загрузки не заменяется сообщением «Нет наблюдений».

## 9. Критерии приёмки

1. Есть перечень утверждённых входных оснований с версиями и ответственными.
   Объём ограниченного этапа без методики, если выбран, отмечен отдельно;
   отсутствие утверждения не маскируется готовностью интерфейса.
2. Проверен цикл модели: черновик, проверка, возврат, публикация, копирование,
   архив. Опубликованные описания/признаки неизменяемы; самоутверждение запрещено.
3. Педагог создаёт наблюдение о разрешённом участнике своего контекста.
   Чужой ученик, чужое занятие, исключённый участник и произвольное событие
   отклоняются сервером. Проверены исторические даты и сохранённый состав.
4. Неполный черновик сохраняется, неполная отправка отклоняется. Факт
   и трактовка не объединяются; будущая дата, чужая версия навыка и закрытый
   источник дают понятные ошибки без потери ввода.
5. Пройден цикл `draft → submitted → reviewed`, возврат с комментарием
   и отзыв подачи. Нельзя редактировать поданную запись в обход перехода,
   подтвердить своё наблюдение или подменить автора.
6. Исправление `reviewed` создаёт редакцию и сохраняет исходную. Новая редакция
   проходит повторную проверку, замена атомарна, двойного учёта нет.
   Отзыв ошибочного факта исключает его из оснований без удаления истории.
7. Новая запись внутренняя. `reviewed` не публикует её автоматически.
   Проверены отдельная публикация, отзыв, невозможность самопубликации,
   снятие старой публикации при утверждении исправления и новая публикация.
8. Отсутствие наблюдений не создаёт нулевой уровень. Без утверждённой методики
   доступна только хронология без вычисленного балла. После её принятия все
   контрольные примеры, недостаточные/противоречивые данные и отзыв источника
   дают ожидаемые результаты с воспроизводимыми основаниями.
9. Одноимённые навыки разных моделей не объединяются автоматически;
   исторический вывод сохраняет версии модели, методики и исходных редакций.
   Фильтр хронологии и пагинация не изменяют сохранённый уровень.
10. Проверены все роли, совмещение ролей, назначенные области, прямые API/URL,
    отзыв доступа, смена педагога/куратора и блокировка между открытием
    и сохранением. Закрытые тексты, источники и их количества не выдаются.
11. Приватные файлы недоступны по чужому ID и после отзыва прав. Публикация
    не расширяет их аудиторию. При отсутствующем файловом модуле нет имитации
    загрузки; зависимость явно отмечена незакрытой для полного запуска.
12. Повторные и конкурентные запросы не дублируют решения, не теряют правки
    и не обходят доступ. Ошибка транзакции откатывает изменение и историю.
    Сбой публикации не оставляет частично открытые данные.
13. Student 360 показывает разрешённую хронологию и источники, сохраняет
    прежние учебные блоки и ограничения на семейные данные. Проверены
    desktop 1440 px, mobile 360 px, клавиатура и все состояния формы.
14. Миграция не создаёт наблюдения из посещаемости, групповых отчётов или
    прогресса. Обновлены API, инструкции и матрица доступа; проверки состояний,
    конкурентности и прав выполнены с PostgreSQL, сквозной сценарий включает
    создание, проверку, публикацию, чтение Student 360, исправление и отзыв.

## Результаты разработки и граница готовности

Поставляются модель и миграция, API наблюдений и истории, проверки прав,
редактор, очередь проверки, публикация в Student 360, интеграция приватных
источников, тесты и отчёт с фактическими результатами. После принятия методики
добавляется проверяемый вывод уровня по её контракту. При успешной приёмке
только ограниченного этапа отчёт прямо указывает: «Хронология реализована,
автоматический уровень не принят»; до проверки нельзя заявлять готовность
даже этого этапа.
Учебные работы и проекты принимаются отдельными задачами месяца 3.
