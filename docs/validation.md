# Проверки модуля авторизации и пользователей

Дата: 12 октября 2026 года.

## Результаты

| Проверка | Результат |
| --- | --- |
| `go test -count=1 ./...` с `TEST_DATABASE_URL` | Пройдено, включая интеграционные тесты PostgreSQL |
| `go vet ./...` | Пройдено |
| `go build ./cmd/server ./cmd/admin` | Пройдено |
| `npm run build` | Пройдено: TypeScript и сборка Vite |
| `go test -race ./...` | Локально не выполнено: Go требует CGO, в окружении нет C-компилятора |

Backend проверен на Go 1.24.3 для Windows/amd64. Интеграционные тесты запускались на отдельном локальном PostgreSQL 17 с отдельными схемами для каждого теста; существующие базы приложения не использовались. Тестовый сервер после проверок остановлен.

## Проверенные сценарии

- Вход без учёта регистра email, запрет дубликатов email и отсутствие публичной регистрации.
- Создание пользователей только администратором, ограничения временного пароля и защита последнего администратора.
- Bcrypt с отдельной солью для каждого хеша; границы длины пароля в символах и байтах UTF-8.
- Случайный токен сессии в cookie и только SHA-256 хеш в PostgreSQL; HttpOnly, SameSite=Strict и Secure при HTTPS.
- CSRF: неверный Origin, другой порт, отсутствие cookie или заголовка, несовпадение токенов; защита POST, PATCH, PUT и DELETE.
- Привязка CSRF к сессии и восстановление CSRF после подмены cookie.
- Отзыв текущей сессии при выходе, всех сессий при смене/сбросе пароля и блокировке; отказ при повторном использовании отозванного токена.
- Замена сессии при повторном входе; неуспешный вход сохраняет текущую сессию.
- Повторная проверка сессии внутри административной транзакции: выход, смена пароля, истечение срока, чужая или отсутствующая сессия.
- Истечение сессии после начала транзакции, пока запрос ждёт блокировку PostgreSQL.
- Одновременный вход со старым паролем и смена пароля; одновременное изменение пользователей и выход.
- Ограничение попыток входа, временная блокировка и одинаковая ошибка для существующего и неизвестного email.
- Команда первого администратора требует явные учётные данные, удаляет пароль из окружения и отказывается повторно инициализировать систему.

В `.github/workflows/ci.yml` настроен запуск `go test -race` с PostgreSQL на Linux. CI в этой локальной проверке не запускался. Инструкции повторного запуска находятся в [README](../README.md#проверки).

## Frontend по брендбуку

После применения `AIQ_Brandbook_Professional_2026.pdf` выполнены `npm run build` и `npm run test:ui`. Пройдено 12 браузерных проверок в установленном Chrome: шесть сценариев для desktop 1440 × 1000 и те же шесть для mobile 360 × 800. На проверенных экранах axe не обнаружил нарушений проверяемых правил WCAG A/AA; горизонтального переполнения нет, видимый основной текст не меньше 16 px. Проверены клавиатура, модальные окна, подтверждения, валидация, сообщения ошибок и пагинация.

Браузерные тесты используют вымышленные ответы API через Playwright route interception. Учебные модули backend не реализованы; их интерфейсы пока не проверены с настоящими API. Автоматическая проверка axe не заменяет пользовательское тестирование со скринридером.

Подробности, контраст, происхождение логотипа и снимки: [дизайн-система frontend](frontend/design-system.md).

## Роли и модуль педагогов

Дополнительно пройдены `go test -count=1 ./...` с PostgreSQL, `go vet ./...`, сборки Go и frontend. Новые интеграционные проверки покрывают фактические HTTP-права администратора, руководителя, педагога и куратора, чужие ID, объединение ролей, отзыв сессии внутри транзакции, CSRF, поиск и пагинацию, нормализацию контактов, уникальность связи с пользователем, очищение nullable-полей и сохранение архивных профилей. Проверена сериализация архива с назначением и сохранение исторического внешнего ключа на тестовом потребителе.

Общая матрица прав и предикаты доступа к полной/минимальной карточке ученика и собственным занятиям проверены unit-тестами. Соответствующие учебные API пока отсутствуют; эта проверка относится к политикам доступа.

Проверки Playwright: 12 прежних сценариев прошли вместе с новым экраном педагогов; после уточнения тестовых селекторов и перезагрузки тестовой сессии прошли четыре новых проверки педагогов (CRUD и ролевой интерфейс для desktop и 360 px). Контраст и размеры текста проверены axe и вычисленными CSS-значениями. Подменённые API в браузерных тестах не используются приложением вне тестов.

`docs/openapi.yaml` прошёл структурную проверку и разрешение ссылок через Swagger Parser: OpenAPI 3.0.3, девять путей. Подробнее: [роли и педагоги](roles-and-teachers.md).
