# M4-12 — карточка бесплатного события

Карточка дополнена [M4-13 — регистрацией и участием](month4-event-participation.md): теперь работают заявки, вместимость, документы, отмена события и уведомления. Ниже описан исходный объём M4-12.

Реализовано 29 октября 2026 года. Раздел «Бесплатные события» (`#/events`) содержит список с поиском по названию, фильтром состояния, страницами по 20 записей и отдельной карточкой. Создание: `#/events/new`; карточка: `#/events/{id}`. Участие бесплатное, поля стоимости нет.

## Поля и заполнение

| Поле | Правило |
| --- | --- |
| Название | Обязательно даже в черновике, 1–200 символов |
| Тип | Свободное название типа, до 100 символов: например, мастер-класс или встреча |
| Описание | До 5000 символов |
| Организатор | Имя человека или название организации, до 200 символов; текстовое поле, без автоматического создания аккаунта |
| Ответственные | До 20 разных действующих сотрудников. Выбор через поиск по имени и страницы; внешние роли без служебной роли и заблокированные аккаунты исключаются |
| Начало, окончание | Абсолютные моменты времени; окончание строго позже начала |
| Часовой пояс | Имя IANA, например `Europe/Moscow`, `Asia/Yekaterinburg`, либо `UTC`; по умолчанию Москва |
| Место | До 1000 символов; допускается описание помещения или адрес |
| Вместимость | Целое число от 1 до 1000000; в черновике допустим 0, означающий незаполненное поле |
| Период регистрации | Начало строго раньше окончания; регистрация заканчивается не позже начала события |
| Условия участия | До 5000 символов |
| Необходимые документы | Текстовый перечень до 5000 символов. Пустое поле означает «Не требуются». Это описание требований, а не загрузка документов участников |
| Статус публикации | `draft`, `published`, `registration_closed`, `completed`; изменяется отдельными действиями |

Черновик можно сохранить только с названием, затем дополнить. Заполненные даты и связи проверяются при каждом сохранении. Для публикации нужны все поля, кроме необязательного перечня документов, минимум один действующий ответственный и положительная вместимость. Начало события и окончание регистрации должны быть в будущем; начало регистрации может уже наступить.

Форма вводит и отображает даты в часовом поясе события, независимо от пояса компьютера. Смена пояса в редакторе сохраняет введённые местные часы: проверьте их перед сохранением. В API время передаётся в RFC3339 с явным смещением или `Z`, а имя часового пояса хранится отдельно. На сервере встроена база часовых поясов Go, поэтому наличие системного zoneinfo не требуется.

Несуществующее местное время при переводе часов и повторяющийся час форма отклоняет с объяснением. В последнем случае можно выбрать время вне повторяющегося часа; интегратор API может указать нужный момент явно через RFC3339. Часовой пояс влияет на представление, а сервер сравнивает абсолютные моменты времени, включая даты регистрации.

## Доступ

- Администратор создаёт и редактирует карточки, выбирает ответственных, публикует, закрывает регистрацию и завершает событие.
- Руководитель читает все карточки, включая черновики.
- Педагог, куратор, методист, руководитель образования, родитель и ученик видят только события после публикации, включая закрытые и завершённые. Назначение ответственным само по себе не выдаёт право редактирования.
- Анонимного каталога нет. Вход и обязательная смена временного пароля проверяются обычными правилами системы.

Список, поиск, счётчики и прямая карточка имеют одинаковую проверку видимости. Для недоступного черновика возвращается `404`. Семейная привязка к конкретному ребёнку для просмотра общих бесплатных событий не требуется. В карточке видны имена ответственных, но не email, телефон и другие сведения учётной записи. Общий поиск сотрудников доступен только администратору.

## Переходы и редактирование

```text
draft → published → registration_closed → completed
```

1. Сохранить черновик и нажать «Опубликовать». Сервер проверяет полноту карточки и актуальность ответственных; фиксирует время публикации.
2. Нажать «Закрыть регистрацию». Действие доступно только для опубликованного события, в том числе для досрочного закрытия; фиксируется время закрытия.
3. После времени окончания события нажать «Завершить событие». Требуется состояние закрытой регистрации. Завершённая карточка остаётся доступной читателям и больше не редактируется.

Обратные переходы, пропуск состояний, удаление и отдельная отмена события в M4-12 не реализованы. До завершения администратор может исправлять карточку; опубликованное содержание после сохранения сразу меняется для читателей. Полная история содержания редакций не заявляется: есть номер редакции и Audit Log с именами изменённых полей.

Переходы выполняются явно. Истечение периода регистрации само по себе не переписывает статус `published`, однако `registration_open` уже становится `false`. Этот признак равен `true` только при `published` и попадании текущего момента в полуинтервал `[registration_starts_at, registration_ends_at)`. В интерфейсе отдельно показаны статус и действие периода регистрации.

Каждое изменение требует текущую `revision`; строка блокируется в транзакции. При параллельных изменениях только один запрос сохраняется, другой получает `409`. Повтор перехода со старой редакцией также отклоняется. Интерфейс сохраняет введённые поля при ошибке, запрещает повтор устаревшего сохранения и предлагает загрузить актуальную карточку. Загрузка явно заменяет несохранённый ввод — перед ней его можно скопировать.

## Хранение, аудит и границы

Миграция `030_free_events.sql` добавляет `free_events` и таблицу связей `free_event_responsibles`. Изменение карточки, состава ответственных и запись аудита атомарны. Проверки дат и состояний продублированы ограничениями БД; триггер запрещает неверный переход и правку завершённой карточки. Роли и сессия заново проверяются в транзакции вместе с административной блокировкой управления.

Audit Log использует тип объекта `free_event` и действия `event.created`, `event.updated`, `event.published`, `event.registration_closed`, `event.completed`. Свободные тексты, адреса и документы в аудит не копируются. Все ответы API имеют `Cache-Control: private, no-store`; операции записи требуют CSRF.

M4-12 реализует карточку и публикацию сведений. Самостоятельная регистрация, заявки, список участников, подсчёт свободных мест, подтверждение/отмена участия, загрузка документов участников и рассылка о событиях сюда не входят. Вместимость пока хранится как параметр, а не как ограничитель фактических заявок. Адаптер уведомлений об участии M4-10/M4-11 остаётся подготовленным для будущего модуля регистрации; изменение карточки не создаёт фиктивное подтверждение участия.

Контракт: [openapi-events.yaml](openapi-events.yaml). Пользовательская инструкция: [раздел 27 руководства](site-user-guide.md#27-бесплатные-события).

## Проверки

`events_integration_test.go` проверяет создание и частичное заполнение, все роли, скрытие черновиков и счётчиков, выбор активных сотрудников, проверки дат и публикации, CSRF, запрет прямой записи статуса, конкурирующие редакции, атомарный откат при ошибке аудита и весь цикл до неизменяемого завершения. `service_test.go` проверяет ограничения полей и часовых поясов. `events.spec.ts` проверяет создание, статусы, сохранение ввода при конфликте, очистку при утрате доступа, семейный просмотр, конвертацию времени и переходы на летнее/зимнее время на desktop и 360 px.

29 октября 2026 года выполнены полный `go test -p 1 ./... -count=1` с отдельной PostgreSQL (пакет `internal/app`: 272,4 секунды), `go vet ./...`, сборки backend и frontend, проверка OpenAPI через Swagger Parser и 8 Playwright-сценариев — успешно. После исправления поиска сотрудников с кириллическими именами на БД с локалью `C` повторены целевые Go-проверки событий, прав и архитектуры, `go vet` затронутых пакетов и сборка backend. Поиск имён нормализуется в Go, выдача и счётчик учитывают одинаковый фильтр.

Мобильная карточка просмотрена визуально; проверки доступности и горизонтального переполнения прошли. UI-тесты используют подменённый API, интеграционные Go-тесты — реальную отдельную БД. Vite сохраняет предупреждение о размере основного JS-файла около 523 кБ. Проверка опубликованного стенда и эксплуатационных процессов резервного копирования этим прогоном не заявляется.
