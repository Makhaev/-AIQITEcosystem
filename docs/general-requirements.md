# Общие требования: реализация и проверка

Этот перечень относится к текущим исходникам AIQ Core. Практическое руководство: [project-guide.md](project-guide.md); запуск, миграции и резервные копии: [README](../README.md) и [operations.md](operations.md).

Эта таблица покрывает общий технический перечень, а не все детали месячного ТЗ. [Сверка с полным ТЗ от 12 октября 2026 года](tz-review.md) отдельно перечисляет функциональные пробелы, отличия контрактов и незавершённые проверки приёмки.

Оставшиеся доработки и их критерии приёмки: [ТЗ на завершение первого этапа](tz-completion.md).

| Требование | Реализация | Проверка / источник |
| --- | --- | --- |
| Миграции БД | Встроенные SQL 001–016, schema_migrations, транзакция, advisory lock; автоматический запуск и отдельный CLI migrate; разделение состава и отметок с сохранением ID | `backend/migrations/`, `platform/database/database.go`, `TestArchitectureMigrationPreservesParticipantsMarksAndHistory`; fixtures повторно применяют миграции |
| Внешние ключи и уникальность | FK связей, уникальный lower(email), аккаунт педагога, семейные связи/основной контакт, модуль/позиция, активное зачисление, занятие/ученик; EXCLUDE расписания | SQL-миграции и интеграционные тесты модулей, включая конкурентные запросы |
| Архивирование вместо удаления истории | Статусы archived, завершение зачисления с датой, перевод в транзакции, снимок журнала; FK без DELETE CASCADE | `TestGeneralHealthAndForeignKeys`, тесты архивов/истории и Dashboard |
| page, page_size; 20 по умолчанию, максимум 100 | Общий контракт всех десяти списков; неверные параметры дают 400 | `TestGeneralListContractAndStablePageBoundaries` |
| items, total, page, page_size | Даже пустая страница содержит массив и метаданные; total учитывает фильтры и права | Тот же общий интеграционный тест и тесты модулей |
| Стабильная сортировка | Каждая сортировка заканчивается ID; audit — DESC, остальные списки — ASC | Репозитории и тест двух страниц педагогов с одинаковыми именами |
| Валидация backend/frontend | Строгий JSON, длины/типы/даты/связи, итоговая PATCH-карточка; формы и сообщения полей | Тесты сервисов/интеграции, Playwright форм |
| code, message, field_errors, request_id | httpx.Fail, собственный X-Request-ID; ошибки прокси также JSON | `TestObserveUsesRouteTemplateAndExcludesPrivateData`, общий интеграционный тест, `frontend/nginx.conf` |
| Структурированные логи без секретов/ПД | JSON slog и nginx access log; без raw errors, IP, URL/query, тел, cookies и контактов | `platform/logging/`, httpx.Observe, тесты исключения приватных значений; job proxy в CI |
| /health/live и /health/ready | Live проверяет процесс; ready делает pool.Ping с таймаутом 2 с, при сбое 503 | `TestGeneralHealthAndForeignKeys`, включая закрытый pool |
| Секреты в окружении, только .env.example в Git | .gitignore исключает варианты .env, дампы, .pgpass; Docker contexts не копируют их; bootstrap без default password | Config, cmd/admin, .env.example, .gitignore, .dockerignore |
| Адаптивность от 360 px | Адаптивные панели, формы, меню, прокрутка таблиц внутри контейнера | Playwright desktop/mobile-360, проверки отсутствия переполнения |
| Загрузка, ошибка, пустой список, успешная запись | ResourceState, Notice, EmptyState; повтор загрузки и блокировка записи | Playwright ui/lessons/tasks/dashboard/audit |
| Только вымышленные demo | Учебный seed не выполняется; тесты и screenshots используют вымышленные записи | `backend/internal/app/*_test.go`, `frontend/tests/`, руководство проекта |
| README: запуск, миграции, администратор, копии | Команды Compose/локального запуска, скрытый ввод пароля, migrate, pg_dump/pg_restore в новую БД | README и operations.md |
| Документация | Руководство, эксплуатация, этот перечень, OpenAPI, контракты модулей, журнал проверок | `docs/` |

Нумерованные страницы стабильны при неизменных данных; конкурентные изменения могут сдвинуть границы страниц. Вложенные массивы карточек и снимок одного журнала не являются самостоятельными пагинируемыми списками. Audit — отдельный журнал с доступом администратора; технические логи не содержат имени автора.

Результаты реально выполненных проверок, включая ограничения Docker и восстановления: [validation.md](validation.md). Наличие команды в документации не означает, что она была исполнена в текущем окружении.
