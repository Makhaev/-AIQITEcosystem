# API пилота

Игровой прогресс ученика: `GET /learning/progress`, только роль `student`. Возвращает `items` с полями `student_id`, `student_name`, `total`, `reviewed`, `submitted`, `assigned` по активным карточкам собственного аккаунта. Параметры ID не расширяют доступ. Задания отменённых занятий исключены; агрегат считается по всем записям, без ограничения списка в 500 строк.

Кабинет методиста `/methodist/*`: [просмотр программ педагогов, прогресса и отчётов](methodist-workspace.md).

Кабинет куратора и отчёты семье (`/curator/*`, `/curator-reports/*`): [правила и API](curator-workspace.md).

Персональные маршруты педагога `/teacher/workspace`, `/teacher/groups`, `/teacher/students` описаны в [документации кабинета педагога](teacher-workspace.md).

Префикс `/api/v1`. JSON, сессионные cookies, Origin и CSRF действуют так же, как в существующем API. Не передавать одноразовый токен в query string: браузерная ссылка использует fragment `/#/access/TOKEN`, погашение выполняется POST-запросом. Все новые операции изменения сохраняют аудит.

| Метод и путь | Доступ и результат |
| --- | --- |
| GET `/features` | Публичные флаги интерфейса; выключенный модуль на сервере возвращает 404 `feature_disabled` |
| POST `/invitations` | Администратор: `{email,name,role,profile_id}`. role: student/parent/teacher. Только активная ещё не связанная карточка. Ответ 201 `{user_id,url,expires_at}` |
| POST `/auth/accept-link` | `{token,password}`. Однократная установка пароля; 204. Недействительная/истёкшая/отозванная ссылка: 400 `invalid_link` |
| POST `/auth/recovery-request` | `{email}`. 202 с одинаковым сообщением для существующего и неизвестного email. Ограничение частоты запросов |
| GET `/access-requests` | Только администратор: до 200 неразрешённых запросов, `{items:[{user_id,name,email,requested_at}]}` |
| POST `/access-links` | Только администратор: `{user_id}` → 201 `{url,expires_at}`; прежние ссылки аннулируются |
| GET `/learning/students` | Карточки `{id,name,status}` в области доступа пользователя |
| GET `/learning/lessons` | Занятия с учеником, группой и педагогом. Семья видит только свои карточки; посещаемость — у завершённых занятий, без внутренних комментариев |
| GET `/assignments` | Администратор/руководитель — все, педагог — свои занятия, куратор — закреплённые дети, ученик — свои задания. Родителю ответы и черновые проверки не выдаются |
| POST `/assignments` | Администратор/педагог своего занятия: `{lesson_id,student_id,title,instructions,due_at?}` → 201 `{id}`. Состав журнала должен быть открыт и содержать ученика |
| POST `/assignments/{id}/submit` | Только связанный ученик: `{answer}` → 204. Только из `assigned` в `submitted` |
| POST `/assignments/{id}/review` | Администратор/педагог своего занятия: `{feedback,accepted}` → 204. Из `submitted` в `reviewed` либо обратно в `assigned` для доработки |
| GET `/reports` | Сотрудники — в своей области доступа; ученик/родитель — только опубликованные отчёты связанных активных карточек |
| POST `/reports` | Администратор/педагог: `{lesson_id,student_id,summary}` → 201 `{id}`. Сохранение нового/обновление неопубликованного черновика |
| POST `/reports/{id}/publish` | Администратор/педагог: 204. Требуются завершённое занятие, минимум одна принятая работа и отсутствие непроверенных заданий ученика этого занятия |

В `learning/*`, `assignments`, `reports` ответ `{items:[...]}`, максимум 500 записей. Опубликованный отчёт нельзя изменить этой операцией; новые задания к тому же отчёту закрыты. Полномочия, актуальность сессии, блокировка и связи проверяются сервером; права записи перепроверяются внутри транзакции.

Поля ограничены по длине: название 200, условие/ответ/отчёт 10000, комментарий проверки 5000 символов. Пароль: минимум 12 Unicode-символов, максимум 72 байта UTF-8. Задания и отчёты отменённого занятия недоступны для новых изменений.

Формальная исходная спецификация остальных модулей остаётся в `openapi.yaml`; этот документ описывает добавленные операции MVP.
