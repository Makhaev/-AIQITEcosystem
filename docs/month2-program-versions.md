## Решения реализации

- Каталог `programs` сохраняет идентификаторы и совместимость Core.
  Название и описание учебного содержания копируются в самостоятельную версию.
  Изменение каталога или старого модуля не меняет опубликованный документ.
- Структура версии хранится единым типизированным JSON-документом в PostgreSQL.
  Ключи разделов, модулей и шаблонов уникальны внутри документа и сохраняются
  при копировании. Сохранение черновика атомарно, с проверкой ревизии.
- У версии независимые номер, статус, автор, отправитель, утверждающий,
  история решений и источник копирования. Комментарий возврата остаётся
  в истории после повторной отправки.
- Педагог/куратор видит только закреплённые за доступными ему группами или
  занятиями опубликованные/архивные версии. Черновики доступны методическим
  ролям, администратору и руководителю для чтения.
- Новые группы требуют опубликованную версию. Ранее существовавшие данные
  переносятся как явно помеченные снимки Core без выдуманного утверждающего
  и без восстановления неизвестных исторических текстов.
- Публикация не обновляет ссылки групп и занятий. Перевод — отдельная операция
  администратора с предварительным просмотром, проверкой актуальности,
  сопоставлением шаблонов и транзакционной записью истории.
- В перевод входят только будущие scheduled-занятия. Начавшиеся, проведённые,
  отменённые занятия и уже сохранённые исторические снимки сохраняются.
- Содержимое опубликованной версии защищается также в БД. Старые миграции
  не изменяются; расширение добавляется следующей миграцией.

## Обязательные проверки

1. Чистая БД и непустой Core 001–016 → новая миграция; повторный запуск.
2. Роли, объектный доступ, отзыв сессии, CSRF; запрет самоутверждения.
3. Полный цикл, возврат с комментарием, повторная отправка, копирование,
   конкурирующие правки и публикация.
4. Запрет изменений published/archived через API и прямой SQL.
5. Привязка только к published, сохранение прежних групп при новой публикации.
6. Чужая программа/модуль/шаблон; устаревший preview; атомарный откат.
7. Перевод будущих занятий, сохранение прошлого, состава, отметок и audit.
8. React/TypeScript сборка, UI desktop/360 px, валидность OpenAPI,
   регрессия Core с настоящим PostgreSQL.

## Как проверить сценарий

1. Администратор назначает разным пользователям роли «Методист» и
   «Руководитель образования».
2. Методист открывает программу → «Новая версия», заполняет структуру,
   сохраняет черновик и отправляет его на проверку.
3. Руководитель возвращает версию с комментарием либо публикует.
   Для правки опубликованной версии методист выбирает
   «Создать новую на основе этой».
4. Администратор выбирает опубликованную версию при создании группы,
   затем шаблон закреплённой версии при планировании занятия.
   Педагог видит полный сохранённый план в карточке своего занятия.
5. В карточке группы администратор выбирает «Перевести на другую версию»,
   просматривает будущие занятия, сопоставляет планы и указывает причину.
   После подтверждения прежние планы доступны в истории переводов.

Повтор тестов (только отдельная тестовая БД):

```powershell
$env:TEST_DATABASE_URL = '<URL тестового PostgreSQL>'
go -C backend test -count=1 ./...
npm --prefix frontend run build
node scripts/m2-e2e.mjs
node scripts/qa/validate-openapi.mjs
```

Полный тест R12 дополнительно требует `R12_TEST_DATABASE_URL` с CREATEDB
и `PG_BIN` с утилитами PostgreSQL. Без них соответствующий тест пропускается,
что нельзя выдавать за полный прогон. `scripts/m2-report.mjs` собирает отчёт
из сохранённых локальных журналов, отклоняет ошибки/пропуски Go и
неустранённые ошибки браузера; сам тесты не запускает.

## Дополнительная доработка 20.10.2026

Повторная проверка выявила ещё три воспроизводимых дефекта. Они закрыты
тестами в `curriculum_content_integration_test.go`:

- **Подробные конспекты.** Общий лимит HTTP 32 КБ отклонял допустимые по
  полям документы. Для сохранения версии и применения перевода выделен
  лимит 1 МиБ всего JSON-запроса в UTF-8, согласованный с существующим
  nginx. Сохранение конспекта и материалов по 20 000 кириллических символов
  проверено с чтением обратно и публикацией. Превышение общего лимита
  оставляет прежнюю ревизию и документ без изменений. Редактор заранее
  сообщает о превышении и сохраняет введённый текст в форме.
- **Историческая корректировка M2.** Название модуля теперь обязательно
  и при наличии `version_module_key`, даже если старый `module_id` равен
  null. Форма показывает это поле. Прежнее название сохраняется в истории;
  опубликованный документ и исходный полный `plan_snapshot` не изменяются.
- **Перевод между программами.** Совпадение строковых ключей не считается
  соответствием модулей независимых программ. Если был выбран модуль или
  шаблон, preview возвращает `needs_mapping=true`, а интерфейс требует
  явно выбрать новый план или сохранение темы без шаблона.

Редактор также позволяет восстановить работу после `stale_revision`:
введённые правки остаются в форме, загрузка актуальной версии требует
подтверждения их замены. Переход через ссылку возврата или основное меню
предупреждает о несохранённых изменениях. Закрытие/перезагрузка вкладки
использует предупреждение браузера. Проверки интерфейса подтверждают
отмену замены, загрузку правок коллеги и последующее сохранение с новой
ревизией.

После этих изменений пройдены **15 целевых интеграционных Go-тестов** M2
и исторических снимков, **20 UI-проверок** редактора и истории,
**2 настоящих E2E M2** на desktop и 360 px, сборки Go/React, `go vet` и
валидация OpenAPI. Результаты этого повторного прогона отделены от
предыдущей полной регрессии в поле `followup`
[JSON-отчёта](reports/m2-local-2026-10-20.json).
Новая миграция для этих исправлений не требуется.
