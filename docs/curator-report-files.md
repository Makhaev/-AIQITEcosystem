# Вложения в отчётах куратора

Куратор открывает ученика → «Отчёты и цели» → «Подготовить отчёт родителям». Под текстом отчёта расположен блок вложений: можно выбрать несколько файлов, перетащить их с компьютера, проверить названия и размеры, убрать лишние до сохранения.

Кнопка «Сохранить черновик» сохраняет текст и загружает выбранные файлы. Если загрузка части файлов не удалась, форма остаётся открытой: текст и успешные загрузки уже сохранены. Повторное сохранение обновляет этот же черновик и отправляет только оставшиеся файлы. Для удаления сохранённого вложения откройте «Изменить черновик» и подтвердите удаление.

Перед публикацией список материалов виден в окне выбора родителей. После публикации материалы доступны получателям в самом отчёте, до блока подробных показателей. Пустого блока вложений нет. Сохранены палитра AIQ, Noto Sans, клавиатурная навигация и мобильная ширина 360 px.

## Хранение и доступ

- До 20 файлов на отчёт; каждый — непустой, до 10 МиБ, имя до 200 символов. Форматы не ограничиваются: документы, фотографии и работы ученика скачиваются как вложения.
- Файлы хранятся в PostgreSQL и входят в резервные копии БД. Миграция `014_curator_report_files.sql` добавляет таблицу и защиту неизменности опубликованных вложений.
- Пока отчёт — черновик, родитель не может скачать файл даже по прямому адресу. После публикации проверяются получатель, актуальная семейная связь и статус ученика. Посторонний родитель или куратор не получает доступ по известному ID файла.
- Добавлять и удалять файлы можно только с правом управления отчётами и доступом к активному ученику. После публикации нельзя добавлять, заменять и удалять вложения; это защищено транзакциями и триггером БД. Для новых материалов нужен новый отчёт.
- Скачивание требует действующую сессию и задаёт `Content-Disposition: attachment`, `application/octet-stream`, `nosniff`, `private, no-store`. Изменения требуют CSRF-токен и записываются в аудит.

## API

`GET /curator-reports` и `GET /curator-reports/{id}` дополнены полем `files: [{id, name, size, created_at}]`, без содержимого файлов. Размер указан в байтах.

| Метод | Путь относительно `/api/v1` | Результат |
| --- | --- | --- |
| POST | `/curator-reports/{id}/files` | Один файл в поле `file`, multipart/form-data; 201 и метаданные |
| GET | `/curator-reports/{id}/files/{file_id}` | Исходные байты после проверки доступа к отчёту |
| DELETE | тот же путь файла | 204; только для черновика |

Ошибки: 400 — некорректный/пустой файл, 403 — нет разрешения, 404 — объект недоступен или не принадлежит отчёту, 409 — опубликованный отчёт, архивный ученик либо лимит количества, 413 — превышение размера.
