# Dashboard

Раздел «Обзор» и `GET /api/v1/dashboard` доступны администратору (`admin`) и руководителю (`leader`). Педагог и куратор не имеют доступа, в том числе по прямому URL. Сессия, блокировка, обязательная смена пароля и актуальные роли повторно проверяются в транзакции чтения.

Ответ содержит шесть показателей:

| Поле | Правило |
| --- | --- |
| `active_students` | Количество учеников со статусом `active`, независимо от числа зачислений |
| `active_groups` | Количество групп со статусом `active` |
| `active_teachers` | Количество профилей педагогов со статусом `active`, включая профили без аккаунта |
| `lessons_today` | Занятия, начинающиеся сегодня по Москве, только `scheduled` и `completed` |
| `attendance_percent` | Посещаемость за выбранный период |
| `overdue_tasks` | Все задачи `todo` или `in_progress` со сроком `due_at < now()`, независимо от исполнителя |

Параметры `date_from` и `date_to` — календарные даты `YYYY-MM-DD`, обе границы включительны по `Europe/Moscow`. По умолчанию — весь текущий московский календарный месяц, включая последний день. SQL использует полуоткрытый интервал до начала следующего месяца. Некорректная дата или начало позже окончания возвращают `400`. Выбор периода меняет только посещаемость; остальные показатели описывают текущее состояние.

Например, октябрь 2026 года преобразуется в `[2026-10-01 00:00+03:00, 2026-11-01 00:00+03:00)`, то есть `[2026-09-30 21:00Z, 2026-10-31 21:00Z)`. Указанный пользователем последний день также преобразуется в начало следующего дня, не включая его. Если передана только одна дата, другая сохраняет независимое значение по умолчанию для текущего московского месяца.

Посещаемость использует ту же функцию, что и Student 360:

```text
(present + late) / (present + late + absent + excused) × 100%
```

Учитываются только включённые в сохранённый журнал строки завершённых занятий, начинающихся в выбранном периоде. `unmarked`, исключённые строки, запланированные и отменённые занятия не участвуют. Архивирование ученика, группы или педагога не удаляет исторические отметки. При пустом знаменателе возвращается `null` («Нет данных»); при одних пропусках — `0`.

Суммируются все отметки всех групп. Например, если в одной группе 2 присутствия/опоздания из 4 отметок, а в другой — 0 из 1, общий процент равен `2 / 5 × 100 = 40%`. Среднее процентов групп дало бы ошибочные `25%`.

Приёмочный пример: `3 present + 1 late + 1 absent + 1 excused` даёт `4 / 6 × 100 = 66,666…%`. API Dashboard и Student 360 сохраняет точность расчёта; оба экрана округляют только отображение до `66,67%`. Пустой набор даёт `null`, отображается «Нет данных», количества отметок равны нулю. Нулевой процент при существующих отметках отображается как `0%`.

Все показатели читаются в транзакции `REPEATABLE READ READ ONLY`. Интерфейс округляет процент до двух десятичных знаков, проверяет порядок дат, повторно загружает тот же период по кнопке «Показать» и позволяет повторить загрузку после ошибки.

Под фильтром явно показан применённый период посещаемости с включительными датами и отметкой МСК. Редактирование полей до нажатия «Показать» не изменяет этот текст; он соответствует отправленным датам, а не несохранённым изменениям фильтра.
