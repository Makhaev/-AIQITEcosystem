# Удаление пользователей

Администратор открывает «Пользователи», нажимает «Удалить» в строке нужной учётной записи и подтверждает действие в окне с именем и email. Отмена ничего не меняет. Собственная учётная запись недоступна для удаления.

`DELETE /api/v1/users/{id}` доступен только администратору с действующей сессией и CSRF-токеном. Авторизация повторно проверяется в транзакции, которая использует общую блокировку административных изменений и блокировку строки пользователя. Возвращает 204; повторное удаление и изменение удалённого пользователя — 404, собственное удаление — 409. После действия должен оставаться активный администратор.

Используется логическое удаление: `deleted_at`, обязательная блокировка аккаунта, завершение всех сессий и погашение всех неиспользованных ссылок приглашения/восстановления. Пользователь исключается из списка, счётчика и списков выбора по ролям. Связанные карточки, учебные записи, файлы и аудит сохраняются; записывается событие `user.deleted`. Email остаётся закреплён за прежней учётной записью. Восстановление через интерфейс не предусмотрено. Это удаление доступа и учётной записи из рабочего списка, а не уничтожение всех персональных данных.

Миграция `018_user_deletion.sql` добавляет столбец и CHECK-ограничение: удалённая запись должна оставаться заблокированной. Существующие аккаунты и учебные данные не удаляются. Миграции выполняются приложением при запуске.

Проверки: интеграционные тесты PostgreSQL для удаления, отзыва двух сессий, запрета входа и изменения удалённой записи, сохранения связанной карточки и истории, списка/счётчика, прав доступа, CSRF и запрета собственного удаления. Playwright проверяет подтверждение/отмену, повтор после ошибки и пагинацию на desktop и ширине 360 px. Существующий тест управления пользователями проверяет клавиатуру и доступность формы.

Перед обновлением нового VPS создан снимок актуальной БД и конфигурации `/root/aiq-migration-backup-20261113-rfx33ef9`, копия с проверенными контрольными суммами сохранена вне VPS в закрытом каталоге `.local/aiq-audit-backup-anj573x7`. Непосредственно перед заменой контейнеров также выполняется `deploy/backup.sh`. Старый сервер и DNS не затрагиваются.

Обновление сохраняет предыдущие образы backend/frontend и архив исходников. При неудаче проверки здоровья до завершения обновления возвращаются прежние образы. Столбец миграции при этом остаётся. После начала использования удаления откат к старому приложению требует отдельной проверки: старый код не учитывает `deleted_at`. Автоматически восстанавливать старую БД нельзя, поскольку это может потерять новые данные.
