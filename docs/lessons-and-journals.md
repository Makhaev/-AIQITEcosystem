# Расписание, занятия и состав журнала

Занятие содержит группу, необязательный модуль программы группы, тему (1–200 символов), педагога, начало, окончание, место проведения (до 500 символов) и статус `scheduled`, `completed` или `cancelled`. По умолчанию — `scheduled`. Новое назначение требует активной группы и неархивного педагога; исторические ссылки на архивные справочники сохраняются.

Начало и окончание принимаются в RFC3339 с часовым поясом, сохраняются в PostgreSQL как `timestamptz` и возвращаются в API в UTC. Окончание строго позже начала с точностью PostgreSQL (микросекунды). Интерфейс вводит и показывает время в `Europe/Moscow`. Фильтры `date_from` и `date_to` — московские даты; конечная дата включается полностью, включая занятия, начинающиеся после полуночи по Москве, но ещё на предыдущую дату UTC.

## Конфликты

Два ограничения `EXCLUDE USING gist` с `btree_gist` запрещают пересечения одного педагога и одной группы. Интервал `[starts_at, ends_at)` допускает смежные занятия. `cancelled` исключается из обоих ограничений; `completed` сохраняет занятый интервал. Проверка выполняется также при редактировании и восстановлении отменённого занятия. Ограничения учитывают незафиксированные записи конкурирующих транзакций; ошибки возвращаются как `409 teacher_overlap` или `409 group_overlap`. Проверки прикладного кода не заменяют ограничения БД.

Миграция `006_lessons.sql` устанавливает доверенное расширение `btree_gist` в схему `public`. Пользователю миграций нужны права установки расширения в базу; при отсутствии таких прав расширение может заранее установить владелец БД. Если в существующей БД есть пересекающиеся неотменённые занятия, миграция отклоняется: исправьте реальные конфликты, прежде чем запускать новую версию. Миграция не отменяет и не перемещает занятия автоматически.

## Состав журнала

Первый `GET /lessons/{id}/attendance` создаёт снимок состава в одной транзакции. Выборка учитывает дату начала занятия в Москве: `starts_on <= дата` и `ends_on IS NULL OR ends_on >= дата`. Дата окончания зачисления включается. Архивирование ученика не удаляет его из исторического состава. Если исторические периоды одного ученика пересекаются, выбирается последнее подходящее зачисление; один ученик включается один раз.

Сохраняются ID исходного зачисления, ID ученика и имя на момент снимка. `roster_initialized_at` фиксируется даже для пустого журнала. Группа блокируется до урока, сериализуя первый снимок с изменением зачислений; повторные и параллельные открытия не пересоздают состав. Первый снимок всех учеников сохраняется целиком даже при открытии куратором, которому возвращаются только его строки. API GET аутентифицирован; этот идемпотентный снимок — предусмотренное внутреннее изменение при чтении журнала.

Перевод, вывод, новое зачисление, переименование ученика или архив группы не меняют снимок и отметки. После создания снимка запрещено менять группу и московскую дату начала занятия; тему, модуль, место, педагога и время в пределах исходной даты можно редактировать с обычной проверкой конфликтов. Отмена сохраняет журнал. При обновлении старой БД уже существующие отметки помечаются как сохранённый журнал.

Администратор явно исправляет состав через `PUT /lessons/{id}/roster`: массив `enrollment_ids` из истории этой группы и обязательная `reason` (1–1000 символов). Пустой массив исключает всех учеников. Разрешено включить историческое зачисление вне исходного периода как осознанную корректировку. Чужая группа, повторяющийся ученик или отсутствие причины отклоняют весь запрос. Данные и audit фиксируются атомарно.

Исключение использует `included=false`, без удаления записи посещаемости. Повторное включение сохраняет её ID, имя, статус и комментарий; при явном выборе другого зачисления этого ученика корректируется ссылка на зачисление. В `audit_logs.details` записываются причина, предыдущие и новые ID зачислений; событие `lesson.roster_corrected` содержит автора, время и ID занятия. Первый снимок записывает `lesson.roster_initialized` один раз. Обычные изменения расписания также попадают в audit.

## API и права

Префикс `/api/v1`; изменение требует Origin и CSRF.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/lessons` | Список, `search`, `status`, `date_from`, `date_to`, `group_id`, `teacher_id`, пагинация |
| POST | `/lessons` | Создание занятия |
| GET | `/lessons/{id}` | Данные занятия и признак сохранённого состава |
| PATCH | `/lessons/{id}` | Редактирование, nullable `module_id` и `location`, изменение статуса |
| POST | `/lessons/{id}/complete` | Статус `completed` |
| POST | `/lessons/{id}/cancel` | Статус `cancelled` |
| GET | `/lessons/{id}/attendance` | Создание/чтение снимка; `lesson_date`, `initialized_at`, `items` |
| PUT | `/lessons/{id}/attendance` | Ввод отметок для учеников сохранённого состава |
| PUT | `/lessons/{id}/roster` | Корректировка состава с причиной и audit |

Администратор управляет расписанием и составом. Руководитель читает всё. Педагог читает собственные занятия и минимальные данные учеников; отмечает только собственный журнал после начала занятия. Куратор читает занятия своих учеников и только их строки журнала. До сохранения снимка доступ куратора определяется подходящими зачислениями на дату занятия, затем — сохранёнными включёнными строками. Несколько ролей суммируются без расширения чужих строк журнала. Полные карточки учеников и контакты родителей не выдаются через журнал.

Завершённый журнал может изменять только администратор, отменённый журнал не принимает новых отметок. Статусы отметок: `unmarked`, `present`, `absent`, `excused`, `late`; комментарий до 500 символов. Корректировки состава доступны администратору для всех статусов занятия. Этот пункт не вводит дополнительных условий завершения занятия на основании отметок: администратор управляет его статусом.
