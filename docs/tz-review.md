# Сверка с полным ТЗ AIQ Core от 12 октября 2026 года

## Вывод

Основной функциональный прототип реализован, но полное соответствие этому ТЗ и завершённая приёмка пока не подтверждены. Исходная сверка основана на проверке исходников, локального Git и ранее сохранённого отчёта тестирования. К 13 октября устранены пробелы P0 и P1; 16 октября выполнен базовый архитектурный вариант R10. Актуальные результаты и оставшиеся обязательные R11–R14: [completion-progress.md](completion-progress.md). Публикация не выполнялась.

[general-requirements.md](general-requirements.md) описывает общий технический перечень предыдущего задания; он не является актом выполнения всех пунктов полного ТЗ.

Оставшиеся работы и критерии приёмки оформлены отдельным документом: [ТЗ на завершение первого этапа](tz-completion.md).

## Что реализовано

- Авторизация по email/паролю, серверные сессии, bcrypt, bootstrap администратора, временные пароли, отзыв сессий, CSRF и лимиты входа.
- Фиксированные роли с серверной проверкой, объектные ограничения педагогов и кураторов, суммирование ролей.
- Пользователи, педагоги, ученики, родители, семейные связи, основной контакт, назначение куратора, поиск, фильтры и архивирование.
- Программы/модули, группы, вместимость, зачисления и перевод с сохранением истории и защитой конкурентных изменений.
- Расписание, конфликт времени группы/педагога, сохранённый состав журнала, атомарная посещаемость, завершение и отмена с проверками.
- Student 360 с контактами для разрешённых ролей, группами, ближайшими занятиями, историей посещаемости и критических изменений.
- Основные задачи, фильтры, переназначение, вычисляемая просрочка; Dashboard с общей формулой посещаемости; административный Audit Log с атомарностью.
- Миграции, FK/уникальные ограничения, пагинация, общие ошибки, health, безопасные технические логи, OpenAPI, Docker-конфигурация, адаптивный UI и документация.

Наличие раздела не означает выполнения всех его деталей: отличия перечислены ниже.

## Эксплуатация и приёмка

| Пункт ТЗ | Статус |
| --- | --- |
| Docker Compose и nginx | Для R11 подготовлены HTTPS Compose и автоматический прогон. Нативный nginx -t и 16 HTTPS-проверок прошли; Docker Engine отсутствует, контейнерный запуск не выполнен. [Отчёт](r11-operations-report.md) |
| HTTPS опубликованного стенда | Нативно проверены TLS, cookies/CSRF, лимиты и реальные отказы. Сервер/домен не предоставлены; публикация и доступ владельца не подтверждены |
| Ежедневный pg_dump, последние семь копий | Есть инструкции ручного копирования. Задание по расписанию, защищённое хранилище и ротация семи копий не настроены в проекте |
| Восстановление в чистую БД | Документировано, но фактическая успешная проверка восстановления отсутствует |
| Нагрузка: 1000 учеников / 100 групп / 10000 занятий / 20 пользователей | Нагрузочный сценарий и отчёт p95 на 2 vCPU / 4 ГБ не найдены; целевые времена не подтверждены |
| Сквозной сценарий в браузере на чистом стенде | Есть PostgreSQL-интеграция и UI-тесты с подменёнными API. Единый полный браузерный сценарий с реальным API/БД не подтверждён |
| Unit-тесты процента и переходов | Добавлены unit-тесты матрицы задач, возраста, календарного периода и общей функции процента (R09, 16.10.2026); отдельные unit-тесты переходов занятия ещё нужны в R13 |
| GitHub и выпуск v0.1.0 | Есть remote, ветка main и CI YAML. В локальной копии нет тега v0.1.0, есть незакоммиченные изменения. Успешный удалённый CI, PR/задачи, приватность репозитория и передача стенда владельцу не подтверждены |
| Согласование и акт приёмки | Согласование полей/прав, недельные демонстрации и принятие заказчиком не устанавливаются по исходникам; требуется отдельное подтверждение |

Локально ранее прошли 63 Go-теста, включая 49 интеграционных, и 62 браузерных сценария на desktop/360 px; сборки, go vet и OpenAPI также проверены. Первый полный Go-запуск имел неустановленный сбой; два последующих полных запуска прошли. Это свидетельства проверок реализованных правил, а не доказательство завершённой приёмки полного ТЗ. Подробности: [validation.md](validation.md).
