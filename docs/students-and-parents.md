# Ученики и родители

Доработки P1: [совпадения контактов, возраст и основной маршрут /overview](completion-p1.md). Результаты проверок: [completion-progress.md](completion-progress.md).

Карточки учеников и семейные связи обслуживает `backend/internal/modules/students`, карточки родителей и проверку совпадающих контактов — `backend/internal/modules/parents`. У обоих модулей отдельные handler/service/repository; общие модели находятся в `internal/domain/people`. Прежняя миграция `003_families.sql` сохранена, а схема развивается новыми миграциями до 016. HTTP-контракты карточек не меняются. Контракт — [OpenAPI](openapi.yaml), структура хранения журнала — [схема БД](database-schema.md).

## Карточки

Ученик: `name`, необязательная `birth_date`, `active`/`archived`, необязательный `curator_id`, ID и время создания/изменения. ФИО — от 1 до 200 символов; дата — существующая дата `YYYY-MM-DD`, не позднее текущей даты по Москве. `null` очищает дату и назначение куратора. Новый куратор должен быть незаблокированным пользователем с ролью `curator`. Историческое назначение сохраняется при последующей блокировке или смене роли пользователя.

Родитель: `name`, `phone`, `email`, `active`/`archived`, ID и время создания/изменения. Обязателен хотя бы один непустой корректный контакт. Телефон нормализуется в международный формат, российское начало 8 — в +7; email — в нижний регистр. PATCH проверяет итоговую карточку: удалить последний контакт нельзя, заменить телефон на email одним запросом можно. Непереданные поля сохраняются, `null` очищает необязательный контакт.

ФИО и родительские контакты не уникальны. Автоматического объединения нет; каждая операция создания возвращает новый ID. Карточки не создают аккаунты, пароль или сессию; кабинетов учеников и родителей нет.

Перед сохранением форма администратора проверяет возможные дубли через `POST /parents/contact-matches`: телефон и email передаются в теле, при редактировании добавляется `exclude_id`. Совпадения включают архивные карточки и показывают только ID, имя, статус и названия совпавших полей. Предупреждение позволяет явно сохранить отдельную карточку; после сбоя нужно повторить проверку. Все страницы совпадений доступны в форме. Совпадение ФИО не вызывает предупреждения. [Контракт и поведение формы](completion-p1.md).

Оба справочника поддерживают `search`, `status`, `page`, `page_size`: страницы по 20 записей, максимум 100. Поиск по ФИО учитывает кириллицу без учёта регистра; для родителей также по нормализованному телефону и email. `%` и `_` ищутся буквально. Порядок стабилен по нормализованному ФИО и ID. Без фильтра статуса возвращаются активные и архивные карточки.

## Семейные связи

`student_parents` содержит `student_id`, `parent_id`, `relationship` (тип представительства, 1–100 символов), `is_primary`. Один родитель может быть связан с несколькими детьми, у ребёнка может быть несколько представителей. Составной первичный ключ запрещает повторную пару, частичный уникальный индекс — второй основной контакт. Эти ограничения действуют независимо от API и при параллельных запросах.

Создание — POST `/students/{id}/parents`; изменение — PATCH `/students/{id}/parents/{parent_id}`. Повторная пара возвращает 409 `link_exists`, второй основной контакт — 409 `primary_contact_exists`. Чтобы сменить основной контакт, сначала снимите признак у текущего, затем назначьте другого. Отсутствие основного контакта разрешено ТЗ.

Новые связи создаются только между активными карточками; иначе 409 `card_archived`. Архивирование выполняется PATCH карточки с `status=archived`, не удаляет карточку или связи. Историческое представительство можно корректировать; восстановление — `status=active`. Физического удаления карточек и связей через API нет.

## Права и транзакции

| Роль | Ученики | Родители | Изменения |
| --- | --- | --- | --- |
| Администратор | Все | Все | Карточки, куратор, связи и архив |
| Руководитель | Все | Все | Нет |
| Куратор | Только закреплённые | Только связанные с закреплёнными учениками | Нет |
| Педагог | Минимальные список, карточка и Student 360 учеников своих занятий | Нет | Нет |

Педагог получает в списке учеников и обычной карточке `/students/{id}` ровно `id`, `name`, `status`. Student 360 (`/overview` и alias `/360`) дополняет их разрешёнными учебными блоками. Ключи даты рождения, возраста, куратора и служебных дат отсутствуют; родители и общая история скрыты. При `teacher+curator` полная проекция доступна только закреплённым ученикам. В доступной [карточке группы](groups-and-enrollments.md) педагог видит только учеников своих занятий; назначение основным педагогом без собственного занятия не раскрывает учеников. Сохранённый состав занятия определяет доступ после фиксации, включая исключённых участников. [Журнал своего занятия](lessons-and-journals.md) не предоставляет контакты родителей.

Middleware проверяет права на каждом маршруте, включая ID. Репозиторий повторно проверяет актуальную сессию, роли и блокировку. SQL ограничивает записи и `total`; чужой ID для куратора возвращает 404. В карточке общего родителя `children` содержит только закреплённых за этим куратором учеников, без имён, количества и данных других детей. Переназначение куратора меняет область доступа на следующих запросах.

Чтение карточки и её связей выполняется в одном снимке PostgreSQL. Изменения сериализуются с управлением пользователями общей административной блокировкой, после которой блокируются строки; ограничения БД дополнительно защищают уникальность связей. Карточка/связь и audit сохраняются в одной транзакции. Контакты и тела запросов не записываются в audit.

## Frontend и проверки

Полная карточка Student 360 (`/overview` и `/360`) возвращает `age`: число полных лет на текущую дату `Europe/Moscow`. Возраст вычисляется при каждом чтении из даты рождения и не хранится отдельным полем БД. Период посещаемости и часовой пояс сервера не влияют на расчёт. Для родившихся 29 февраля в невисокосном году возраст увеличивается 1 марта. Без даты рождения API возвращает `age: null`, интерфейс показывает «Не указано»; возраст 0 отображается числом. В ограниченной карточке педагога ключ `age` и строка возраста отсутствуют.

`frontend/src/screens/Families.tsx` использует общие AIQ-компоненты и тему брендбука. Есть поиск, фильтр, пагинация, карточки, создание/редактирование, выбор куратора, подтверждение архива и восстановление. В карточке ученика доступны поиск родителя по всем страницам, выбор представительства и основного контакта, исправление связи и переход в карточку родителя. В карточке родителя — связанные ученики. ID показываются для различения совпадающих ФИО; в выборе родителей также показан контакт.

Интеграционные тесты с настоящим PostgreSQL проверяют создание, nullable PATCH, обязательный контакт, дату, кириллицу, пагинацию, совпадающие ФИО, семейные связи, архив, отсутствие аккаунтов, роли и чужие ID, общий родитель, переназначение куратора, отзыв сессии, CSRF, ограничения БД и конкурентные попытки создать дубликат/второй основной контакт.

Playwright проверяет формы, контакты, карточки, связи, конфликт основного контакта, архив и восстановление, интерфейс чтения, ошибки ID, Tab/Escape/возврат фокуса, отсутствие переполнения и текст от 16 px. Проверки выполнены для 1440 × 1000 и 360 × 800; axe не обнаружил нарушений проверяемых правил WCAG A/AA. Ответы API в браузерных тестах вымышленные; права и БД отдельно проверены интеграционными тестами Go.
