# Личный кабинет педагога

Стартовая страница после входа пользователя с ролью `teacher`: `/#/teaching`. Для аккаунта с ролями admin и teacher сохраняется административная стартовая страница, а персональный кабинет доступен отдельным пунктом меню.

Основание: раздел 4.2 «Ограничение видимости» в `AIQ_TZ_1_month.docx` и раздел 5 «Кабинет педагога» в гайде разработки. Реализация остаётся в границах текущего MVP: ближайшее занятие, группа и ученики, журнал, задания и отчёты. Редактор конспектов, материалы и расширенные показатели из общего гайда этим изменением не добавляются.

## Что видит педагог

- Свой профиль и специализацию.
- Количество своих групп, доступных учеников и занятий сегодня по московскому времени.
- Количество работ на проверке и неопубликованных отчётов по собственным занятиям.
- Пять ближайших запланированных занятий, включая уже начавшееся: тема, группа, программа, модуль, время, место, переход в журнал и состав.
- «Мои группы»: основное назначение или назначение на занятие, программа, статус, численность текущего состава. Поиск, фильтр и пагинация.
- «Мои ученики»: ФИО, учебный статус и группы собственных занятий. Доступен просмотр по одной группе. Контакты родителей, дата рождения, куратор и полная история в этот список не входят.
- Переходы к собственному расписанию, заданиям, отчётам и доступной карточке ученика Student 360, если включён её флаг.

Назначение основной группе позволяет видеть её в списке. Имена учеников доступны по составу собственных неотменённых занятий, как требует ТЗ. До первого назначения занятия группа может отображаться без доступного списка учеников.

После первого открытия журнала состав сохраняется: позднее зачисление или перевод не расширяет список учеников уже сохранённого занятия. Для ещё не открытого журнала используются даты зачислений на московскую дату занятия. Замена педагога на отдельном занятии даёт доступ к этой группе и её составу для занятия; отменённое занятие само по себе доступ не предоставляет.

## Настройка администратором

1. В «Педагоги» создать/открыть профиль и связать его с правильной учётной записью с ролью teacher либо пригласить педагога через «Приглашения и доступ».
2. Назначить основной профиль педагога группе.
3. Зачислить учеников и создать занятие с этим педагогом. Основной педагог группы и педагог конкретного занятия — отдельные назначения.
4. Войти аккаунтом педагога и открыть «Кабинет педагога».

Если профиль не связан с аккаунтом, кабинет показывает явное сообщение и инструкцию обратиться к администратору. Пустые списки и ошибки загрузки сопровождаются пояснением и возможностью повторить запрос.

Для локальной существующей группы «группа 1» по явному подтверждению пользователя профиль №1 «Адат Вахабова» связан с учётной записью №2. Изменение записано в аудит; группа, ученики и учебная история сохранены.

## API и безопасность

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | `/api/v1/teacher/workspace` | `profile`, `counts`, `upcoming_lessons` |
| GET | `/api/v1/teacher/groups` | `items`, `total`, `page`, `page_size` |
| GET | `/api/v1/teacher/students` | `items`, `total`, `page`, `page_size`, выбранная `group` |

Списки поддерживают `search`, `status`, `page`, `page_size` (1–100, по умолчанию 20). Ученики дополнительно поддерживают `group_id`; чужая или несуществующая группа возвращает одинаковый 404. Поиск буквальный, без интерпретации `%` и `_` как шаблонов.

Идентификатор педагога берётся из действующей сессии. Передавать `teacher_id` или `user_id` в запросе нельзя. Текущие права и сессия повторно проверяются в транзакции; список и общее количество вычисляются в одном снимке Repeatable Read. Даже если у пользователя дополнительно есть роль администратора или куратора, личный кабинет показывает данные только его педагогического назначения. Чистая роль admin/leader/curator/student/parent доступа к персональному API педагога не даёт.
