# M4-06 — кабинет родителя

Родитель после входа открывает `#/family`. Главная выбирает первого доступного ребёнка. При нескольких детях можно переключиться через поле «Ученик»; поиск и страницы списка учитывают только действующие подтверждённые семейные связи. Аккаунт с дополнительной служебной ролью сохраняет обычную служебную стартовую страницу и может открыть семейный раздел через меню.

## Главная ребёнка

- **Ближайшие занятия и расписание:** до пяти неотменённых запланированных занятий, включая начавшееся и ещё не окончившееся. Состав определяется зафиксированным журналом или зачислением на дату занятия. «Всё расписание» открывает список с поиском, периодом по Москве и страницами по 20 записей.
- **Посещаемость за период:** по умолчанию текущий московский месяц. Даты включаются целиком. Учитываются только включённые участники завершённых занятий; незаполненные отметки исключены. Формула: `(присутствовал + опоздал) / (присутствовал + опоздал + отсутствовал + уважительная причина) × 100%`. Нет отметок — нет данных, а не 0%. Выбор периода влияет только на посещаемость.
- **Программа и прогресс:** текущие зачисления, версии и существующий взвешенный прогресс программы группы. Внутренние отчёты и состав группы не выдаются. Личные счётчики целей и выполненных заданий доступны отдельно.
- **Опубликованные результаты:** проверенные опубликованные наблюдения с разрешением родителям для текущей редакции. **Работы ребёнка:** разрешённые семейным API попытки со своим статусом. Внутренние интерпретации, контекст и история решений скрыты; права на вложения проверяются отдельно.
- **Опубликованные отчёты:** до пяти последних опубликованных отчётов для семьи, с доступными файлами. Черновики и отозванные публикации не выдаются.
- **Доступные события:** учебные события — предстоящие занятия и сроки активных заданий. Срок показан как целый московский день. Просроченные задания остаются в разделе «Задания», но не входят в предстоящие события; закрытие задания убирает его срок из событий. Есть общий список с поиском и постраничной навигацией.
- **Мои обращения:** только обращения текущего пользователя по выбранному ребёнку и ответы. Переписка другого родителя и ученика не раскрывается. Из блока можно открыть историю и отправить новый вопрос куратору.

В M4-09 ссылка открывает [полную карточку обращения](month4-parent-requests.md) с сообщениями, вложениями, ответственным, статусом и историей. Отдельный пункт «Мои обращения» содержит все доступные обращения автора и позволяет создать общее обращение без ребёнка. Такой сценарий доступен и родителю без подтверждённых детей, если его собственная карточка активна и привязана к аккаунту.

Главная показывает до пяти записей в каждом списке; кнопки открывают полные списки. Финансового раздела нет.

## Переключение и отзыв доступа

Смена ребёнка размонтирует весь экран обучения, отменяет запросы и сбрасывает раздел, страницы, поисковые фильтры, период и несохранённое обращение. Новый экран открывается с главной. До получения ответа показывается загрузка; поздний ответ предыдущего ребёнка игнорируется. Обновление и ошибка запроса очищают ранее загруженную сводку. При отсутствии подтверждённых детей отображается пояснение.

Каждый API-запрос заново проверяет сессию, роли, привязку, активность карточек и подтверждение связи. Дополнительная служебная роль не расширяет семейный доступ. Ответы имеют `Cache-Control: private, no-store`. Скачивание файлов продолжает проходить через существующие защищённые маршруты.

## Контракт и проверки

- `GET /api/v1/family/students/{id}/parent-home?from=YYYY-MM-DD&to=YYYY-MM-DD` — сводка родителя; без дат используется текущий московский месяц. Обе даты задаются вместе, начало не позже окончания.
- `GET /api/v1/family/students/{id}/events?page=1&search=...` — только учебные события доступного ребёнка, ближайшие первыми, по 20 записей.
- `GET /api/v1/family/students/{id}/lessons` дополнительно принимает `from` и `to` для расписания. Без периода возвращает все доступные занятия.
- Прежний `/home` остаётся главной собственного кабинета ученика.

Новые таблицы и миграции не требуются. Контракт: [openapi-family.yaml](openapi-family.yaml).

Проверки: `parent_portal_integration_test.go` (разные дети, московские границы, формула, публикации, события, обращения), расширенный `family_security_integration_test.go` (отзыв на новых маршрутах), `parent-portal.spec.ts` (медленные ответы при переключении, очистка форм, пустой доступ, desktop/mobile и доступность). UI-тесты используют подменённый API; серверные сценарии — отдельный PostgreSQL.

Локальная проверка 28 октября 2026 года: `go test -count=1 ./...` с отдельным PostgreSQL, `go vet ./...`, `npm run build` и 14 UI-сценариев кабинетов родителя, ученика и управления семейным доступом прошли. Скриншоты desktop и mobile-360 просмотрены. Проверка резервирования с отдельным `R12_TEST_DATABASE_URL` в этот прогон не входила; опубликованный стенд не проверялся.
