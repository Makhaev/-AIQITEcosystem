# Подтверждение локальной готовности MVP

Проверено 4 ноября 2026 года. Среда: Windows, Go 1.24.3, локальная PostgreSQL 17.11, Chrome. Frontend собран через npm с зависимостями из lock-файла. Публичный сервер в эту проверку не входил.

| Проверка | Результат |
| --- | --- |
| Исходный набор Go-тестов с PostgreSQL до изменений | PASS |
| Полный финальный `go test -count=1 ./...` с PostgreSQL | PASS, пакет интеграционных тестов 204,930 с |
| `go vet ./...` | PASS |
| Сборка команд server и admin | PASS |
| `npm run build` | PASS: TypeScript и Vite |
| Регрессионные браузерные проверки | Все 44 подтверждены: 42 PASS в общем прогоне и 2/2 PASS при отдельном повторе |
| Живая браузерная приёмка MVP с настоящим API | 2/2 PASS, desktop и mobile-360, отдельная БД |
| Восстановление резервной копии в отдельную БД | PASS, `pg_restore --exit-on-error` |
| Сохранение существующих данных после миграции | PASS, количества записей до/после совпали |
| Локальный `/health/ready` после обновления | 200, `{"status":"ok"}` |
| Публичный HTTPS, Docker на сервере, внешний backup | Не проверено: домен/сервер и внешнее хранилище не предоставлены |

Живая приёмка прошла приглашение трёх ролей, установку пароля, вход, журнал и завершение занятия, выдачу задания, ответ ученика, проверку, сохранение невидимого семье черновика, публикацию, просмотр результата родителем, выход и восстановление пароля по вручную переданной ссылке. На новых экранах проверены отсутствие JavaScript-ошибок, горизонтального переполнения и нарушений проверенных правил WCAG 2 A/AA и 2.1 AA через axe.

Серверная приёмка дополнительно проверяет две независимые семьи, чужих учеников и педагогов, запрет доступа к черновикам, отзыв семейной связи, возврат задания на доработку, блокировку публикации до готовности, повторное/просроченное/конкурентное использование ссылок и закрытые серверные флаги. Эти проверки не являются полноценным внешним аудитом безопасности или нагрузочным испытанием.

Во время проверки исправлены перехват клавиатурного фокуса при открытии раздела и отсутствие явного обновления списка запросов восстановления. Для полного набора временных таблиц увеличено время очистки тестовых схем на Windows; для длинных браузерных сценариев увеличен общий timeout без ослабления утверждений тестов.

В параллельном общем прогоне две проверки завершились ошибкой записи файлов трассы: одновременно запущенная живая приёмка очищала общий каталог артефактов. Для живой приёмки выделен отдельный `.cache/live-test-results`; обе затронутые проверки отдельно повторены успешно, 2/2 PASS за 16,9 с. Утверждения тестов не ослаблялись.

Восстановленная резервная копия содержит те же количества записей. Резервная копия, полные логи проверок и временные базы остаются локальными; секреты и дампы не добавляются в Git. Тестовые аккаунты живой приёмки созданы в отдельной БД и не попали в рабочие семейные карточки.

Снимки семейного кабинета после публикации: [настольный экран](pilot/screenshots/parent-desktop.png), [мобильный экран 360 px](pilot/screenshots/parent-mobile.png).

Для выпуска по HTTPS остаются: назначить домен и сервер, проверить Docker-конфигурацию на целевой машине, настроить DNS, получить сертификат, организовать внешние резервные копии и повторить приёмку на опубликованном адресе. Локальные тесты не заменяют эти шаги.
