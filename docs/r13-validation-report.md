## Воспроизведение

Команды выполняются из корня с Node 22.12+, Go, PostgreSQL с `btree_gist`,
клиентами PostgreSQL, nginx и Playwright Chromium. Все URL БД должны указывать
на отдельный тестовый кластер. `TEST_DATABASE_URL` без значения пропускает
интеграционные тесты, такой результат не принимается.

```powershell
$env:TEST_DATABASE_URL = '<URL отдельного тестового PostgreSQL>'
$env:R12_TEST_DATABASE_URL = $env:TEST_DATABASE_URL
$env:PG_BIN = '<каталог pg_dump/pg_restore/psql>'
New-Item -ItemType Directory -Force .cache/r13 | Out-Null
Push-Location backend
go test -count=1 -json ./...
go vet ./...
go build -buildvcs=false ./...
go build -o ../.cache/r13/fixture.exe ./cmd/r13-fixture
go build -o ../.cache/r13/admin.exe ./cmd/admin
go build -o ../.cache/r13/server-final.exe ./cmd/server
Pop-Location
Push-Location frontend
npm ci
npm run build
npx playwright install chromium
npm run test:ui
Pop-Location
Push-Location scripts/qa
npm ci
npm run check
Pop-Location
$env:R13_TEST_MODE = 'synthetic'
$env:R13_ADMIN_URL = $env:TEST_DATABASE_URL
node scripts/r13-proxy-config.mjs .cache/r13/proxy '<каталог nginx>'
# Запустить nginx с -p <абсолютный .cache/r13/proxy/> -c nginx.conf
node scripts/r13-e2e.mjs
node scripts/r13-proxy-check.mjs
```

В Linux имена бинарников без `.exe`, переменные через `export`, каталог nginx
обычно `/etc/nginx`. Полный Linux-порядок записан в job `browser-real` в
[CI](../.github/workflows/ci.yml), его удалённый результат ещё не получен.

Для нагрузки: `fixture create-load <новый config.json>` при
`R13_TEST_MODE=synthetic` и `R13_ADMIN_URL` создаёт новую случайную БД с маркером
`AIQ R13 SYNTHETIC ONLY`. Существующий config не перезаписывается. Запустите
backend с URL из этого закрытого файла и `APP_ORIGIN`, соответствующим
`R13_ORIGIN`; не включайте файл с паролем в отчёты. Команда
`node scripts/r13-load.mjs <config.json> <report.json>` воспроизводит профиль
5+15 минут и отказывается от конфигурации без synthetic, правильного имени
БД, типа load и 20 тестовых пользователей. До/после запустите
`fixture inventory <config.json>` и сравните JSON. Не используйте рабочий
кластер даже при наличии защит от перезаписи.

Для повторения локального лимита используйте [r13-windows-host.ps1](../scripts/r13-windows-host.ps1)
с новым `RunDir`, предварительно `initdb` в `RunDir/pg-data`, путями `PgBin`,
`BackendExe`. Скрипт запускает PostgreSQL 55436, затем по маркеру `start-api`
backend 18183 с `RunDir/fixture.json`; `stop` завершает его дочерние процессы.
Генератор запускается отдельно. Для целевого Linux-стенда ограничиваются вся VM
и совместно размещённые БД/приложение; фиксируются ресурсы и способ мониторинга.
