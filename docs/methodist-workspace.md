# Кабинет методиста

Кабинет доступен роли `methodist`, стартовый маршрут — `#/methodology`. Это развитие образовательного контура из гайда AIQ поверх ядра MVP: используются реальные программы, группы, отчёты, посещаемость и задания.

Основное меню: «Обзор», «Программы», «Реализация программ». Отчёты педагогов и кураторов и прогресс учеников находятся внутри «Реализации программ». Профиль и настройки доступны отдельно. Верхняя панель содержит заголовок, профиль и уведомления о последних реальных отчётах; отдельного признака прочтения нет.

Методист может:

- Обзор: активные ученики и программы, количество и последние отчёты педагогов и кураторов.
- Ученики: поиск, статус, текущие группы и программы; карточка содержит историю зачислений, педагогов, посещаемость, принятые работы, сравнение с предыдущим периодом и отчёты обоих типов.
- Программы: создавать и редактировать программы и модули, менять порядок модулей, архивировать и восстанавливать программы. Используются существующие статусы `draft`, `active`, `archived`. На компьютере редактор показывает дерево «программа → модули» и выбранный элемент; на телефоне дерево открывается отдельной выдвижной панелью.
- Реализация программ: программы действующих групп, педагог, количество модулей и активных учеников на текущую московскую дату; поиск по программе, педагогу или группе. По каждой группе показано количество проведённых занятий и общее число неотменённых занятий, включая запланированные. Каталог программ включает и программы без действующих групп.
- Отчёты педагогов: ученик, автор, занятие, программа, содержание и статус публикации.
- Отчёты кураторов: ученик, автор, период, итоги, рекомендации, цели и сохранённые при публикации показатели.

В обоих списках отчётов доступны период, поиск по имени ученика или автора, статус публикации и пагинация. Черновики доступны методисту.

## API

Пути относительно `/api/v1`, требуют действующей сессии роли `methodist`.

| GET | Параметры |
| --- | --- |
| `/methodist/workspace` | — |
| `/methodist/students` | `search`, `status`, `page`, `page_size` |
| `/methodist/students/{id}` | `from`, `to` |
| `/methodist/programs` | `search`, `page`, `page_size` |
| `/methodist/teacher-reports` | `student_id`, `from`, `to`, `search`, `publication`, `page`, `page_size` |
| `/methodist/curator-reports` | те же параметры |

Списки возвращают `items`, `total`, `page`, `page_size`. Поиск до 200 символов, `%` не трактуется как шаблон. `publication`: пустое значение, `draft` или `published`; `status`: пустое значение, `active` или `archived`. При изменении фильтра интерфейс возвращается на первую страницу.

Методист читает программы и модули через `/programs`; создаёт через `POST /programs`, изменяет через `PATCH /programs/{id}`, создаёт модули через `POST /programs/{id}/modules`, изменяет через `PATCH /programs/{id}/modules/{module_id}`. Права повторно проверяются в транзакции, изменения сохраняются в аудите. Модули архивной программы менять нельзя до восстановления. Изменение журналов, заданий и публикация отчётов этой ролью запрещены сервером. Семейные контакты не входят в методические представления.

Прогресс — фактические показатели посещаемости и заданий. Процент освоения программы не рассчитывается: для него нужен отдельный учёт прохождения модулей.

Материалы, разделы внутри программ, шаблоны занятий, версии, отправка на утверждение, модели навыков и задачи по содержанию не имеют реализованного API. Их кнопки и пункты меню скрыты. Описание модуля сохраняет существующий текстовый контент, но не заменяет отдельную библиотеку материалов или конспектов. Текущие статусы программы не являются процессом согласования.

## Проверка

`backend/internal/app/methodist_integration_test.go` проверяет API с PostgreSQL, пагинацию, фильтры, создание и редактирование программ и модулей, архив, прогресс, ограничения роли и изоляцию семейных данных.

`frontend/tests/methodist-workspace.spec.ts` проверяет меню, создание программы и модуля, дерево содержания, уведомления, прогресс, оба вида отчётов, фильтры, ограничения роли, мобильную ширину и доступность. Данные API в браузерном тесте подменяются; сервер проверяется отдельным интеграционным тестом.
