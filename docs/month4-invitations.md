# M4-01 — приглашения родителей и учеников

Дата реализации: 24 октября 2026 года. Изменение добавлено в существующий Core следующей миграцией `021_invitations.sql`.

## Доступные сценарии

Администратор открывает **«Приглашения»**, вводит email, выбирает роль «Родитель» или «Ученик», находит активную существующую карточку и нажимает «Отправить приглашение». Письмо автоматически передаётся настроенному SMTP-серверу. В списке видны получатель, роль, ссылка на карточку, автор, даты создания и истечения, статус.

Статусы: «Ожидает принятия», «Срок истёк», «Отозвано», «Использовано». Статус истечения определяется по времени базы при чтении и принятии; отдельная фоновая задача для истечения не нужна. Администратор может отозвать неиспользованное приглашение или отправить новое. Использованную запись нельзя повторно отправить или отозвать: для прекращения доступа аккаунт блокируется через «Пользователи».

Ссылка открывает отдельную страницу принятия. Для нового email пользователь задаёт и подтверждает пароль; имя берётся из выбранной администратором карточки. Для существующего email нужно войти именно в этот аккаунт и затем подтвердить принятие. При чужой активной сессии сначала предлагается выход. Временный пароль существующего аккаунта требуется сменить обычным механизмом.

После успешного принятия новый пользователь автоматически выполняет обычный вход. Если вход после активации не удался, подтверждение активации сохраняется и предлагается войти отдельно; токен повторно не принимается. В «Моём аккаунте» видны собственные подключённые карточки.

## Правила и реализация

| Требование | Реализованное поведение |
| --- | --- |
| 48 часов | `expires_at` равен `created_at + 48 hours`; время задаёт БД, равенство защищено ограничением |
| Безопасный токен | 32 байта из `crypto/rand`, кодирование base64url; в БД только 32-байтный SHA-256 |
| Роль и привязка только с сервера | Принятие допускает только `token` и `password`; неизвестные JSON-поля отклоняются. Email, роль, карточка и имя берутся сервером |
| Без автоматических семейных связей | Создаются только `parent_accounts` / `student_accounts`. Таблица `student_parents` не изменяется |
| Одноразовое использование | Проверяются использование, отзыв и срок; недействительная ссылка возвращает `410 invitation_invalid` |
| Атомарность | Аккаунт, роль, привязка, использование и audit сохраняются одной транзакцией; ошибка откатывает всё |
| Конкурентное принятие | Общая блокировка изменений и блокировка строки приглашения; срок повторно проверяется перед фиксацией использования |
| Существующий аккаунт | Обязательны его действующая сессия и совпадение ID аккаунта с email приглашения; чужая сессия возвращает 403, анонимный запрос — 401 |
| Повторная отправка | Новая запись и токен на 48 часов; все прежние неиспользованные приглашения той же роли для email или карточки отзываются атомарно |

Одна карточка связана с одним аккаунтом. Аккаунт может иметь одну карточку родителя и одну карточку ученика. Несовместимая уже существующая привязка отклоняется, а не перезаписывается. Архивная карточка не может принять приглашение. Смена email или телефона в справочнике не создаёт и не меняет эту привязку.

Публичной регистрации и формы заявки нет. Роли `parent/student` не выбираются в обычной форме создания сотрудника и не дают доступа к справочникам, образовательным источникам или служебным разделам. Новые учебные кабинеты, доступ родителя к детям и доступ ученика к работам остаются следующими задачами M4. Принятие приглашения активирует идентичность и привязку, не заменяя будущую объектную политику кабинетов.

## Настройка автоматических писем

Backend читает следующие переменные окружения при запуске:

| Переменная | Назначение |
| --- | --- |
| `SMTP_HOST` | Адрес почтового сервера |
| `SMTP_PORT` | Порт; по умолчанию 587 для STARTTLS, 465 для TLS при прямом запуске |
| `SMTP_TLS_MODE` | `starttls` (по умолчанию) или `tls` для шифрования с начала соединения |
| `SMTP_FROM` | Email отправителя без отображаемого имени |
| `SMTP_USERNAME` | Имя пользователя SMTP |
| `SMTP_PASSWORD` | Пароль приложения / SMTP-пароль из защищённого окружения |
| `APP_ORIGIN` | Точный адрес сайта, доступный получателю; используется для ссылки в письме |

Используется проверяемый TLS не ниже 1.2. Незашифрованный режим и отключение проверки сертификата не предусмотрены. Логин и пароль должны быть заданы вместе; для доверенного SMTP relay без авторизации оба могут отсутствовать. Compose и HTTPS-конфигурация передают эти переменные в backend. Для TLS на 465 в Compose задайте и порт, и режим явно.

Вне Compose сервер не загружает `.env` автоматически. Установите переменные в окружении процесса и перезапустите backend. Секрет не добавляется в репозиторий. Пример имён настроек находится в [.env.example](../.env.example).

Для внешних получателей `APP_ORIGIN=http://localhost:5173` непригоден: такой адрес откроет компьютер получателя. Нужен доступный им адрес экземпляра сайта. Приёмка отправки реальных писем требует реквизитов SMTP и этого адреса; в ходе реализации использованы только локальный тестовый SMTP и вымышленные получатели.

Если настройки отсутствуют, создание или повторная отправка возвращает 503 до создания новой записи. Если соединение или отправка завершились ошибкой, новое приглашение отзывается и возвращается 502; предыдущая ссылка не восстанавливается. В редком случае неопределённого ответа SMTP получатель может получить уже отозванное письмо — нужно выполнить повторную отправку. Успешный ответ означает, что SMTP-сервер принял письмо, но не гарантирует его попадания во входящие вместо спама.

Отправка синхронная, с ограничением времени. Автоматической очереди повторных доставок нет: повторный выпуск инициирует администратор. Открытый токен существует только в памяти до передачи письма. Он не хранится в очереди, списке приглашений или audit. Если процесс аварийно завершился после записи приглашения до отправки письма, администратор выпускает новое приглашение.

## API и данные

Контракт: [openapi-invitations.yaml](openapi-invitations.yaml), подключён к [общему OpenAPI](openapi.yaml).

| Метод и маршрут относительно `/api/v1` | Доступ |
| --- | --- |
| `GET /invitations` | Администратор, 20 записей на страницу |
| `POST /invitations` | Администратор; email, role, card_id |
| `POST /invitations/{id}/resend` | Администратор; адресат и связь берутся из прежней записи |
| `POST /invitations/{id}/revoke` | Администратор |
| `POST /invitations/inspect` | По действующему токену, CSRF обязателен |
| `POST /invitations/accept` | По токену; сессия обязательна для существующего аккаунта |
| `GET /account/links` | Только собственные связи действующего аккаунта |

Токен в ссылке находится во фрагменте `/#/invitation?token=…`, который не отправляется веб-серверу как URL запроса. API получает его в теле POST. Используются действующие механизмы Origin/CSRF, ограничения JSON и безопасные HTTP-логи. После успешного принятия интерфейс удаляет токен из текущего адреса.

Миграция добавляет таблицы `invitations`, `parent_accounts`, `student_accounts` и расширяет допустимые роли. Прежние семейные и учебные данные не переносятся и не связываются по совпадениям контактов. Перед обновлением существующей базы требуется резервная копия; миграция применяется штатным сервером или `cmd/migrate`.

## Проверки

Интеграционные проверки используют отдельные схемы в тестовой базе; реальным получателям письма не отправляются.

- `TestInvitationsUnconfiguredMailDoesNotCreateInvitation`: отсутствие SMTP возвращает 503 и не создаёт запись приглашения.
- `TestInvitationsNewAccountHashBindingAndScope`: срок, нормализация email, хеш токена, отсутствие токена в списке, запрет подмены роли/карточки, CSRF, привязки и отсутствие новых семейных связей, запрет служебных API внешней роли.
- `TestInvitationsExistingAccountRequiresMatchingLiveSession`: обязательный вход нужного аккаунта, запрет замены пароля, отозванная сессия и конфликт привязок.
- `TestInvitationsResendExpiryRevocationAndMailFailure`: новый токен, недействительность старого, истечение, отзыв, сбой доставки, отказ при архивной карточке без создания аккаунта.
- `TestInvitationsConcurrentAcceptanceAndRollback`: два конкурентных запроса дают ровно одно успешное принятие; сбой audit откатывает аккаунт, роль, связь и использование, после чего токен можно принять успешно.
- `TestSMTPDeliveryRequiresVerifiedTLS`: письмо передаётся локальному тестовому SMTP через STARTTLS и TLS с проверкой сертификата; проверяются конверт, ссылка и описание срока.
- `TestSMTPConfigurationRejectsMissingAndPlaintextSettings`: отклонение отсутствующих и небезопасных настроек.
- `frontend/tests/invitations.spec.ts`: новый и существующий аккаунт, чужая сессия, недействительная ссылка, административная отправка/повтор/отзыв и ошибка настройки; desktop и 360 px, accessibility.

Команды:

```powershell

```

```powershell

# PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH либо установите браузер Playwright.

```

Из корня: `npm run check --prefix scripts/qa`. Проверка реального SMTP провайдера и доступности ссылки на сервере выполняется после настройки окружения.
