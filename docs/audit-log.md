# Audit Log

«История действий» (`#/audit`) доступна только администратору. Руководитель, педагог и куратор не могут читать журнал даже по прямому ID. API повторно проверяет актуальные роли, блокировку, обязательную смену пароля и сессию внутри транзакции чтения.

## Поля записи

| Поле | Содержание |
| --- | --- |
| `id` | ID записи журнала |
| `occurred_at` | Время события; интерфейс отображает его по Москве |
| `actor_id`, `actor_name` | ID и текущее имя пользователя; `null` для системного события или неуспешного входа неизвестного пользователя |
| `action` | Стабильный код события, например `user.updated` |
| `object_type`, `object_id` | Тип и ID изменённого объекта; ID может быть `null` у неуспешного входа |
| `changed_fields` | Названия реально изменённых полей; значения не записываются |
| `request_id` | ID запроса из серверного `X-Request-ID`; входящий пользовательский ID не используется |

Исторические записи до миграции `010_audit_log.sql` имеют пустой `changed_fields`: прежние значения не восстанавливаются и изменения не выдумываются. Повторное сохранение тех же данных может создать событие с пустым массивом; служебные timestamps, поисковые копии и отображаемые имена связанных объектов не считаются пользовательскими изменениями.

## События и атомарность

Записываются создание и изменение пользователей, ролей и блокировок; сброс и смена пароля (только факт, поле `password`); карточки педагогов, учеников, родителей, программ и модулей; назначения пользователя педагогу, куратора ученику, программы/педагога группе; семейные связи; состав групп (зачисление, вывод, перевод); расписание и статусы занятий; инициализация/корректировка состава журнала, посещаемость; создание, изменение, переназначение и статусы задач. Сохраняются существующие события входа, неуспешного входа и выхода.

Audit-запись создаётся через ту же `pgx.Tx`, что и данные. Ошибка audit откатывает само изменение, связанные изменения и отзыв сессий. Перевод ученика сохраняет вывод, новое зачисление и оба события в одной транзакции. Ошибки валидации или конфликтов не создают событие успешного изменения. `REPEATABLE READ READ ONLY` обеспечивает согласованность количества и страницы журнала.

Пароли, хеши, cookie, токены, email и телефоны не сохраняются в новых audit-записях. Там есть только названия соответствующих полей. Значения названий, описаний задач, комментариев посещаемости и причин корректировки также не записываются: произвольный текст может содержать контакты или секреты. Новая корректировка состава сохраняет в `details` только прежние/новые ID зачислений и факт предоставления причины; `details` не выдаётся API. Миграция сохраняет исторические записи без удаления прежних данных; старые `details` могут содержать ранее записанный текст причины, но API его не возвращает.

## API чтения

- `GET /api/v1/audit-logs`: список, новые записи первыми (`occurred_at DESC, id DESC`).
- `GET /api/v1/audit-logs/{id}`: одна запись; неизвестный ID — `404`.

Фильтры `actor_id`, `action`, `object_type`, `object_id`, `request_id` сравниваются точно и объединяются через AND. `date_from` и `date_to` — даты `YYYY-MM-DD`, включительно по Москве; границы необязательны. `page` — 1…1000000, `page_size` — 1…100 (по умолчанию 20). Некорректные даты/ID/пагинация, обратный период и строки длиннее 128 символов возвращают `400`.

POST, PUT, PATCH и DELETE коллекции или записи возвращают `405` для администратора. Неавторизованный запрос получает `401`, остальные роли — `403`. UI не содержит кнопок создания, редактирования или удаления. Дополнительно PostgreSQL запрещает UPDATE и DELETE audit-записей триггером `audit_logs_append_only`.
