# R12 — отчёт проверки 19 октября 2026

Реализация и локальная приёмка прошли. Машиночитаемое доказательство:
[`reports/r12-native-2026-10-19.json`](reports/r12-native-2026-10-19.json),
`passed: true`, 16 проверок. Команды эксплуатации: [инструкция R12](backup-r12.md).

Испытание выполнено на отдельном временном кластере Windows, PostgreSQL **17.5**,
`pg_dump` / `pg_restore` **17.6**, loopback `127.0.0.1:55434`. Использованы только
синтетические данные. Тест создавал свои случайные исходную и восстановленную БД;
после проверки обе удалены, тестовая роль удалена, кластер остановлен.
Рабочая БД не подключалась и не перезаписывалась.

Контрольный набор включает двух пользователей, ученика, родителя и семейную
связь, педагога, программу, группу, зачисление, завершённое занятие, участника,
отметку `present`, сохранённую версию учебного снимка, задачу и 19 записей audit.
Все значения, включая исторические снимки и ссылки, сверены с тем же snapshot,
который использовал `pg_dump`. Точные количества и хеши находятся в JSON.

Подтверждено:

- Восемь последовательных суточных сроков через планировщик оставляют семь
  архивов; самая старая копия удаляется, повторный запуск в тот же день пропускается.
  Отдельно daemon действительно дождался следующей минуты по реальным часам
  и выполнил копию. Для теста изменено время, рабочее значение осталось 03:00.
- Отсутствие маркера хранилища, недоступные утилиты и настоящий отказ `pg_dump`
  из-за отсутствия SELECT дают failed и ненулевой health. Семь прежних архивов
  сохранились побайтно; временные файлы убраны.
- Параллельный запуск блокируется, не перезаписывая статус активного задания.
  После выдачи `pg_read_all_data` роль без прав записи успешно создаёт копию;
  успешный повтор очищает состояние сбоя и сохраняет ротацию.
- Повреждённый архив отклоняется по SHA-256 **до создания** целевой БД.
- Настоящий `pg_restore` в новую БД из `template0` завершился одной транзакцией,
  с восстановлением FK/ограничений; количества, значения всех строк и миграции совпали.
- Через отдельный HTTP router выполнены вход восстановленным аккаунтом,
  проверка сессии, Student 360, журнала, истории снимков, задач и audit.
  Отметка посещаемости и задача дополнительно сверены по значениям.
- После этих проверок повторный контроль исходной тестовой БД показал отсутствие
  изменений от восстановления и входа в восстановленное приложение.

`restore.status` в JSON фиксирует результат команды восстановления **до** HTTP-
проверок: `database_verified_application_checks_required`. Их последующий успех
подтверждают верхний `passed: true` и `checks` с `restored_login_and_session`,
`student_history_attendance_tasks_audit_http`.

Дополнительно прошли `go test ./...`, `go vet ./...` и сборка `cmd/backup`.
Общий `go test ./...` запускался без `TEST_DATABASE_URL`: прежние интеграционные
сценарии приложения в нём пропускались; R12 отдельно выполнен с настоящим PostgreSQL.
Добавлен CI job `backup-r12`, использующий тот же приёмочный тест на Linux.
Удалённый CI и Docker-образ локально не запускались: Docker недоступен.

Эксплуатационная приёмка пока не подтверждена: тестовое хранилище было локальным,
а не отдельным зашифрованным носителем. На целевом сервере нужно подключить
защищённое хранилище и ACL, установить постоянную службу, согласовать внешний
мониторинг/уведомления, подтвердить ежедневный запуск и повторить восстановление
реальной копии с контрольным набором. Отчёт не заявляет, что эта инфраструктура
уже настроена.
