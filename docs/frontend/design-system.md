# Frontend AIQ: тема и компоненты

Дизайн реализован по `AIQ_Brandbook_Professional_2026.pdf`: логотип — страницы 10–11, палитра — страница 12, типографика — страница 13, digital — страница 21. Применение цветов к кнопкам, карточкам и навигации — рабочая адаптация для интерфейса.

## Тема

Все цвета определены в `frontend/src/theme.css`. Шесть фирменных значений перенесены точно: `#087F3D`, `#05652F`, `#1D1D1B`, `#F7F8F6`, `#EAF5EE`, `#FFFFFF`. Отдельно определены семантические цвета ошибок, предупреждений, границ и вспомогательного текста. В остальных CSS-файлах цвета задаются только через переменные.

Фон приложения — светлый Canvas `#F3F5F2`, карточки и формы — белые. Шесть исходных фирменных цветов сохранены. Дополнительные оттенки Forest и Sage определены в `theme.css` для выделенной карточки, вводных блоков и декоративных элементов. Зелёный используется для основных действий, статусов, активной навигации и фокуса. Основной текст — AIQ Ink. Noto Sans Regular и Semibold подключены локально с кириллицей и латиницей; внешние сервисы шрифтов не используются. Лицензия включена в `frontend/public/fonts/NotoSans-OFL.txt`.

Основной текст, поля, кнопки, таблицы и ссылки навигации — не менее 16 px; вспомогательные подписи в шапке и названия групп навигации — 12–14 px. Заголовки — 600. Единый шаг отступов, скругления контролов 10 px, карточек 18 px и окон 22 px. Кнопки и поля — от 48 px по высоте; ссылки бокового меню — 46 px. Статусы всегда содержат текст.

## Общие компоненты

`frontend/src/components/ui.tsx`: Button, Input, PasswordInput, Select, Card, Table, Modal, Badge, Pagination; дополнительно Notice, PageHeading и EmptyState. Основной Layout и мобильная навигация — `frontend/src/components/Layout.tsx`.

PasswordInput используется на входе, при смене пароля и в формах пользователей. Кнопка «Показать пароль»/«Скрыть пароль» управляет только своим полем, сохраняет введённое значение и не отправляет форму. Связь с полем и состояние доступны через `aria-controls` и `aria-pressed`; переключение работает с клавиатуры.

Input и Select связывают подписи, подсказки и ошибки через идентификаторы. Modal использует native dialog, удерживает Tab/Shift+Tab внутри окна, закрывается по Escape и возвращает фокус к элементу открытия. При сохранении повторные действия заблокированы. Таблица на узком экране превращается в строки с подписями полей, сохраняя табличные роли. Навигация показывает `aria-current`, доступна ссылка перехода к содержимому; учтён reduced motion.

## Экраны и границы интеграции

Рабочие экраны существующего backend: вход, пользователи, создание/изменение пользователя, блокировка/разблокировка, смена и обязательная смена пароля; педагоги — список, поиск, профиль, создание/редактирование, архивирование и восстановление. Для педагогов используется отдельный типизированный экран `frontend/src/screens/Teachers.tsx`. Ученики и родители подключены через `frontend/src/screens/Families.tsx`: карточки, поиск, фильтры, пагинация, редактирование, архив, куратор и семейные связи.

Подготовлены интерфейсы групп и состава, расписания с представлениями списком и по дням, занятия с журналом посещаемости, задач, обзора и истории действий. Они используют общую тему, загрузку, пустые состояния, ошибки, формы и пагинацию. Время отображается в Europe/Moscow. Карточка ученика теперь показывает реальные сведения и родителей; учебные показатели будут добавлены вместе с соответствующими модулями.

API педагогов, учеников, родителей, программ и модулей реализованы в Go backend и описаны в OpenAPI. Остальные учебные API ещё не реализованы. Их frontend-модели и обращения являются заготовкой интеграции, а не утверждённым серверным контрактом. При ответе 404 экран сообщает, что раздел готовится к запуску, и запрещает создание записей. Поддельные данные, сохранение только в браузере и имитация успешных операций в приложение не включены.

Рабочий экран `frontend/src/screens/Programs.tsx` содержит список программ, поиск, фильтр статуса, пагинацию, модальные формы, карточку с модулями, редактирование порядкового номера и обработку конфликта. Архив сохраняет содержимое; изменение модулей доступно после восстановления. Все роли получают соответствующий интерфейс чтения/управления, а права дополнительно проверяются сервером.

Перед реализацией остальных учебных модулей необходимо определить их точные схемы в OpenAPI. В заготовке используются CRUD `/groups`, `/lessons`, `/tasks`; детали групп содержат `enrollments`; посещаемость — GET/PUT `/lessons/{id}/attendance`; переходы занятия — POST `/lessons/{id}/complete` и `/cancel`; агрегаты — `/dashboard` и `/audit-logs`. Справочники выбора в этих заготовках пока ограничены первыми 100 записями. В рабочих модулях педагогов и семей список пользователей загружается по всем страницам, поиск родителя имеет серверную пагинацию. Перевод между группами, учебная история, переходы задач и коррекция посещаемости требуют следующих этапов интеграции.

## Проверки и снимки

Воспроизводимые тесты — `frontend/tests/ui.spec.ts`, конфигурация — `frontend/playwright.config.ts`. Проверки запускаются для 1440 × 1000 и 360 × 800. API подменяется тестовыми ответами только внутри тестов. Это проверка интерфейса, а не доказательство работоспособности отсутствующих учебных API.

Для запуска после `npm ci`:

```powershell
npm run build
npx playwright install chromium
npm run test:ui
```

Для установленного Chrome на Windows можно вместо установки браузера задать:

```powershell
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:ui
```

Тесты проверяют точную палитру, шрифт, размер текста, отсутствие горизонтального переполнения, WCAG A/AA через axe, обход полей клавиатурой, удержание и возврат фокуса, пагинацию, создание пользователя, сообщения ошибок, подтверждение блокировки, мобильное меню и ввод посещаемости. CI включает эти проверки.

Контраст: Ink/Warm White — 15,85:1; белый/Green — 5,11:1; белый/Deep Green — 7,22:1; Deep Green/Soft Green — 6,46:1. Ошибки — 6,78:1, предупреждения — 6,61:1. Граница поля на белом — 4,17:1.
