# Frontend AIQ: тема и компоненты

Дизайн реализован по `AIQ_Brandbook_Professional_2026.pdf`: логотип — страницы 10–11, палитра — страница 12, типографика — страница 13, digital — страница 21. Применение цветов к кнопкам, карточкам и навигации — рабочая адаптация для интерфейса.

## Тема

Все цвета определены в `frontend/src/theme.css`. Шесть фирменных значений перенесены точно: `#087F3D`, `#05652F`, `#1D1D1B`, `#F7F8F6`, `#EAF5EE`, `#FFFFFF`. Отдельно определены семантические цвета ошибок, предупреждений, границ и вспомогательного текста. В остальных CSS-файлах цвета задаются только через переменные.

Фон приложения — Warm White, карточки и формы — белые. Зелёный используется для основных действий, статусов, активной навигации и фокуса. Основной текст — AIQ Ink. Noto Sans Regular и Semibold подключены локально с кириллицей и латиницей; внешние сервисы шрифтов не используются. Лицензия включена в `frontend/public/fonts/NotoSans-OFL.txt`.

Текст элементов интерфейса — не менее 16 px; заголовки — 600. Единый шаг отступов, скругления контролов 8 px, карточек 12 px и окон 16 px. Интерактивные кнопки и поля — от 48 px по высоте. Статусы всегда содержат текст.

## Логотип

`frontend/public/brand/aiq-logo.png` извлечён из оригинального изображения на странице 10 PDF. Сохранены все пиксели RGBA, прозрачность, композиция и размер 2102 × 2400. Логотип не перерисован, не обрезан и не перекрашен. В интерфейсе ширина полной версии — 120 px, высота вычисляется автоматически; предусмотрено охранное поле 36 px.

SHA-256 файла: `003c03794a258ba439dcd2373deec56088d508d8c20cf8196d02d2bff8871470`.

## Общие компоненты

`frontend/src/components/ui.tsx`: Button, Input, Select, Card, Table, Modal, Badge, Pagination; дополнительно Notice, PageHeading и EmptyState. Основной Layout и мобильная навигация — `frontend/src/components/Layout.tsx`.

Input и Select связывают подписи, подсказки и ошибки через идентификаторы. Modal использует native dialog, удерживает Tab/Shift+Tab внутри окна, закрывается по Escape и возвращает фокус к элементу открытия. При сохранении повторные действия заблокированы. Таблица на узком экране превращается в строки с подписями полей, сохраняя табличные роли. Навигация показывает `aria-current`, доступна ссылка перехода к содержимому; учтён reduced motion.

## Экраны и границы интеграции

Рабочие экраны существующего backend: вход, пользователи, создание/изменение пользователя, блокировка/разблокировка, смена и обязательная смена пароля; педагоги — список, поиск, профиль, создание/редактирование, архивирование и восстановление. Для педагогов используется отдельный типизированный экран `frontend/src/screens/Teachers.tsx`.

Подготовлены интерфейсы педагогов, учеников, родителей, групп и состава, программ и модулей, расписания с представлениями списком и по дням, занятия с журналом посещаемости, Student 360, задач, обзора и истории действий. Они используют общую тему, загрузку, пустые состояния, ошибки, формы и пагинацию. Время отображается в Europe/Moscow. На карточке ученика контакты родителей скрыты для роли педагога.

API педагогов реализован в Go backend и описан в OpenAPI. Остальные учебные API ещё не реализованы. Их frontend-модели и обращения являются заготовкой интеграции, а не утверждённым серверным контрактом. При ответе 404 экран сообщает, что раздел готовится к запуску, и запрещает создание записей. Поддельные данные, сохранение только в браузере и имитация успешных операций в приложение не включены.

Перед реализацией учебных модулей необходимо согласовать их точные схемы в OpenAPI. В заготовке используются CRUD `/teachers`, `/students`, `/parents`, `/programs`, `/groups`, `/lessons`, `/tasks`; детали групп и программ содержат `enrollments` и `modules`; Student 360 — `/students/{id}/overview`; посещаемость — GET/PUT `/lessons/{id}/attendance`; переходы занятия — POST `/lessons/{id}/complete` и `/cancel`; агрегаты — `/dashboard` и `/audit-logs`. Справочники выбора пока ограничены первыми 100 записями. Связи родителей, перевод между группами, переходы задач и редактирование истории посещаемости требуют следующих этапов интеграции и соответствующих форм.

## Проверки и снимки

Воспроизводимые тесты — `frontend/tests/ui.spec.ts`, конфигурация — `frontend/playwright.config.ts`. Проверки запускаются для 1440 × 1000 и 360 × 800. API подменяется тестовыми ответами только внутри тестов. Это проверка интерфейса, а не доказательство работоспособности отсутствующих учебных API.

Для запуска после `npm ci`:

```powershell
npm run build
npx playwright install chromium
npm run test:ui
```

Для установленного Chrome на Windows можно вместо установки браузера задать:

```powershell
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:ui
```

Тесты проверяют точную палитру, шрифт, размер текста, отсутствие горизонтального переполнения, WCAG A/AA через axe, обход полей клавиатурой, удержание и возврат фокуса, пагинацию, создание пользователя, сообщения ошибок, подтверждение блокировки, мобильное меню и ввод посещаемости. CI включает эти проверки.

Контраст: Ink/Warm White — 15,85:1; белый/Green — 5,11:1; белый/Deep Green — 7,22:1; Deep Green/Soft Green — 6,46:1. Ошибки — 6,78:1, предупреждения — 6,61:1. Граница поля на белом — 4,17:1.
